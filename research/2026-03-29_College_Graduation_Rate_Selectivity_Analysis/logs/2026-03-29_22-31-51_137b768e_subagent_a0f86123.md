## Core Principles - NON-NEGOTIABLE

These five principles must guide ALL data science work. They are not optional.

### Principle 1: Data Robustness First

**ALWAYS check data before operating on it.**

Before ANY analysis or transformation:
- Check shape, types, and memory usage
- Examine value distributions and ranges
- Identify and characterize missing values (count, percentage, pattern)
- Understand what uniquely identifies each row (granularity)
- Look for outliers and anomalies

Be VERBOSE about what you're checking and what you find. Never assume data is clean.

```python
# ALWAYS start with this pattern
print(f"Shape: {df.shape}")
print(f"Columns: {df.columns.to_list()}")
print(f"Types:\n{df.dtypes}")
print(f"Null counts:\n{df.null_count()}")
print(f"Sample:\n{df.sample(5)}")
```

This principle applies only when you are conducting actual data work. Do NOT conduct net new analyses or data inspections when tasked with compiling past work (e.g., analytic notebook creation), or synthesizing prior analyses into a report (e.g., final report writing).

### Principle 2: Documentation First

**ALWAYS understand or create data documentation.**

Before analysis:
- Seek data dictionaries, schemas, or documentation
- Understand where data comes from (provenance)
- Learn collection methods and their implications
- Identify known quality issues or caveats
- Clarify what each column means in business context

If documentation doesn't exist, CREATE IT as you learn about the data.

### Principle 3: Verify Every Operation

**NEVER assume a transformation worked correctly.**

For EVERY data operation:
- Check row counts before and after
- Examine random samples of affected rows
- Validate that expected changes occurred
- Confirm no unintended side effects
- Document what you checked and what you found

```python
# Before transformation
print(f"Before: {len(df)} rows, columns: {df.columns.to_list()}")
sample_before = df.filter(pl.col("id").is_in([1, 42, 100]))

# After transformation

sample_after = result.filter(pl.col("id").is_in([1, 42, 100]))
print(f"Sample comparison:\nBefore:\n{sample_before}\nAfter:\n{sample_after}")
```

### Principle 4: Thorough Code Documentation (ENFORCED)

**Write extensive comments explaining your reasoning. This is MANDATORY, not optional.**

In research workflows, follow the **Inline Audit Trail (IAT)** standard (see `agent_reference/INLINE_AUDIT_TRAIL.md`). The IAT standard is enforced during QA review — scripts with sparse documentation receive WARNING findings.

Every code block should explain:
- WHAT you're trying to accomplish (the goal) → IAT Type 2: Intent Comment
- WHY you chose this approach (the reasoning) → IAT Type 3: Reasoning Comment
- WHAT assumptions you're making (the dependencies) → IAT Type 4: Assumption Comment

For tests and validations, explain:
- What behavior you're checking
- What would indicate success vs. failure
- Why this check matters

### Principle 5: Focus on Research Questions

**Balance rigor with usefulness.**

Always consider:
- What question are we actually answering?
- What level of rigor does this decision require?
- Are there multiple valid approaches with different tradeoffs?
- Should I check with the user before proceeding?

CHECK IN with users when:
- Multiple valid methodologies exist
- Tradeoffs between precision and practicality arise
- Findings are surprising or counterintuitive
- Scope might need adjustment

## Essential Workflows

### New Data Workflow

When you receive new data, ALWAYS follow this sequence:

1. **Load and inspect** (do not transform yet)
   ```python
   # Load data
   df = pl.read_csv("data.csv")  # or scan_csv for lazy
   
   # Immediate inspection
   print(f"Shape: {df.shape}")
   print(f"Columns: {df.columns}")
   print(f"Types:\n{df.dtypes}")
   print(f"First 5 rows:\n{df.head()}")
   print(f"Last 5 rows:\n{df.tail()}")
   print(f"Random sample:\n{df.sample(5)}")
   ```

2. **Check data quality**
   ```python
   # Missing values
   print(f"Null counts:\n{df.null_count()}")
   print(f"Null percentages:\n{df.null_count() / len(df) * 100}")
   
   # Duplicates
   print(f"Duplicate rows: {len(df) - len(df.unique())}")
   
   # Unique values per column
   for col in df.columns:
       print(f"{col}: {df[col].n_unique()} unique values")
   ```

3. **Understand distributions**
   ```python
   # Numerical columns
   print(df.describe())
   
   # Categorical columns - value counts
   for col in df.select(pl.col(pl.String)).columns:
       print(f"\n{col}:\n{df[col].value_counts().head(10)}")
   ```

4. **Identify granularity**
   ```python
   # What uniquely identifies a row?
   # Test candidate keys
   candidate_keys = ["id", "user_id", ["user_id", "date"]]
   for key in candidate_keys:
       cols = [key] if isinstance(key, str) else key
       unique_count = df.select(cols).n_unique()
       print(f"{cols}: {unique_count} unique vs {len(df)} rows")
   ```

5. **Document findings** before proceeding

## Common Pitfalls

| Pitfall | Issue | Solution |
|---------|-------|----------|
| "All graduates" claims | Scorecard covers Title IV recipients only, not all students | Note Title IV limitation prominently in any analysis |
| Wage comparison | Comparing to BLS wages or Census income uses different populations | Use for relative comparisons, not absolute claims; document population differences |
| Ignoring suppression | Many programs have no data due to privacy thresholds | Check suppression rates before analyzing; document coverage |
| Time lag ignored | Earnings reflect old cohorts (6-year = data from 7+ years ago) | Document data vintage and cohort years explicitly |
| Total borrowing assumption | Scorecard debt includes only federal loans, not private | State "federal loans only" when reporting debt figures |
| String codes from docs | Original Scorecard uses string labels; Portal uses integers | Verify actual data types in Portal parquet files; use integer codes |

## Critical Limitation: Title IV Recipients Only

**The single most important caveat for all Scorecard analysis:**

Scorecard tracks ONLY students who received federal financial aid (Title IV):
- Pell Grants
- Federal student loans (Direct, Perkins, PLUS)
- Federal work-study

| Excluded Group | Impact |
|----------------|--------|
| Full-pay students | Often higher-income; different outcomes |
| Students with only state/institutional aid | Missing from data |
| International students | Not eligible for federal aid |
| Some graduate students | If they received no federal aid |

**Coverage varies dramatically by institution type:**

| Institution Type | Typical Title IV Coverage |
|-----------------|---------------------------|
| For-profit colleges | 80-90%+ |
| Community colleges | 60-80% |
| Public flagships | 50-70% |
| Selective private colleges | 30-50% |

**Data systematically overrepresents lower-income students** who are more likely to need federal aid.

| Default (FSA) | 1996-2020 | 2020-2021 | Close match |
| Inst Characteristics | 1996-2020 | 2020-2021 | Close match |
| Repayment (NSLDS) | 2007-2016 | 2020-2021 | **4-5 years stale** |

**Impact:** The student characteristics data (pct_first_gen, family income, dependency status) from Scorecard are too old for a 2020-2021 analysis. The student body composition at many institutions changed significantly between 2016 and 2020-2021, particularly due to enrollment shifts and COVID-19 impacts.

**Mitigation:** Use IPEDS for student demographics (enrollment by race, Pell shares from SFA survey) which have 2020-2021 data. Only use Scorecard for variables IPEDS cannot provide (earnings, repayment, detailed family income distributions).

### 2. Title IV Population Bias (CRITICAL)

Scorecard tracks ONLY students who received federal financial aid. Coverage varies dramatically:

| Institution Type | Typical Title IV Coverage | Bias Direction |
|-----------------|---------------------------|----------------|
| For-profit colleges | 80-95% | Near-complete; data representative |
| Community colleges | 60-80% | Moderate gap |
| Public 4-year (non-flagship) | 60-75% | Moderate gap |
| Public flagships | 50-70% | Significant gap |
| Private non-profit | 50-70% | Significant gap |
| Elite/selective privates | 30-50% | **Large gap -- data covers minority of students** |

**Impact on this analysis:** Since we are analyzing the relationship between graduation rates and *selectivity*, the most selective institutions have the lowest Scorecard coverage. At an elite private with 35% Title IV coverage, Scorecard demographics represent a systematically different subpopulation (lower-income, more likely first-gen, more likely URM) than the full student body. This creates a correlation between selectivity and measurement bias that directly confounds our analysis.

**Direction of bias by metric:**
- Earnings: **understated** (excludes higher-income full-pay students)
- Debt: **overstated** (by definition; non-borrowers excluded)
- Completion: **understated** (lower-income students face more completion barriers)
- Demographics: **biased toward lower-income** students

**Mitigation:** Use IPEDS for demographic variables that cover the full student body. If using Scorecard earnings as an alternative outcome, note that selectivity-earnings comparisons have built-in bias (more selective = lower coverage = more biased sample).

### 3. Completion Rates Not in Portal

The Portal does NOT have a separate Scorecard completion rates dataset. Completion variables (`C150_4`, etc.) are only in the original Scorecard bulk downloads at `collegescorecard.ed.gov`.

**Impact:** For graduation rate analysis, we must use IPEDS graduation rates (`ipeds/colleges_ipeds_grad-rates`), not Scorecard.

**Mitigation:** This is not a problem -- IPEDS is the standard source for graduation rates. But it means Scorecard adds less value to this particular analysis than initially expected.

### 4. Earnings Data Excludes Key Populations

Earnings are measured only for students who are:
- Working (have W-2 income)
- NOT enrolled in further education

This means:
- Graduate school students are excluded (fields with high grad school rates like biology, pre-law show *inflated* earnings because low earners are still in school)
- Self-employed individuals (1099 income) are excluded
- Non-working individuals are excluded

### 5. Data Lag in Earnings

6-year earnings reflect students who entered 7+ years before the data release. 10-year earnings reflect students from 11+ years ago. For the Portal data (earnings through 2018), the 6-year earnings in the most recent year would reflect an entry cohort from approximately 2012 -- nearly a decade before our target analysis period.

### 6. Pandemic Effects (2020-2023)

Default and repayment data from 2020-2023 are distorted by the federal payment pause:
- $0 payments counted as "on track"
- CDR (cohort default rate) artificially low
- Forbearance protected from default

If using 2020 default data, it will not reflect normal repayment behavior.

### 7. Suppression Patterns

| Data Type | Typical Suppression Rate |
|-----------|--------------------------|
| Institution-level earnings | 5-15% |
| Disaggregated earnings (by income) | 30-50% |
| Field-of-study earnings | 40-60% |
| Small institution data | 20-40% |

Suppression threshold: fewer than 30 students with positive earnings leads to suppression. This disproportionately affects small and specialized institutions.

## PITFALLS

### Pitfall 1: Using Scorecard for Variables That IPEDS Provides Better (CRITICAL)

**The mistake:** Fetching `student_body_nslds` for Pell share, racial demographics, or enrollment composition.

**Why it breaks:** (a) Pell share (`PCTPELL`) is NOT in the Portal Scorecard datasets. (b) Racial enrollment shares (`UGDS_BLACK`, `UGDS_HISP`) are NOT in the Portal Scorecard datasets. (c) Even the variables that ARE available (like `first_gen_student_pct`) only go through 2016 and cover only Title IV recipients. IPEDS provides these for the full student body with more recent years.

**Detection:** Check column listings before building fetch scripts. The Portal Scorecard has only 6 datasets with specific column sets documented in the skill.

**Avoidance:** Use IPEDS for: enrollment by race (`fall-enrollment`), Pell share (`sfa`), admission rates (`admissions`), control type (`directory`), graduation rates (`grad-rates`). Use Scorecard ONLY for: earnings, debt, repayment, default, family income details, first-gen share (if 2016 data is acceptable).

### Pitfall 2: Treating `-3` as a Valid Numeric Value in Earnings

**The mistake:** Computing `mean(earnings_med)` without filtering out `-3` suppression codes.

**Why it breaks:** `-3` is an integer code, not a valid earnings value. Including it drastically reduces computed averages. For example, ~24,000 rows in the earnings dataset have `-3` in `earnings_mean`.

**Detection:** Check for negative values in earnings columns: `df.filter(pl.col("earnings_med") < 0)`. If you see `-3` values, suppression codes are present.

**Avoidance:** Always apply the triple filter: `is_not_null() & != -3 & > 0`.

### Pitfall 3: Using Wide-Format Variable Names on Portal Data

**The mistake:** Looking for columns named `MD_EARN_WNE_P6` or `PCTPELL` in Portal data.

**Why it breaks:** The Portal restructured Scorecard data into LONG format with lowercase names. `MD_EARN_WNE_P6` becomes `earnings_med` filtered by `years_after_entry == 6`. The column literally does not exist.

**Detection:** Column not found errors. The Portal column names are all lowercase.

**Avoidance:** Consult the variable-definitions reference. Always use Portal column names (lowercase, LONG format).

### Pitfall 4: Conflating Home ZIP Demographics with Student Demographics (Treasury Dataset)

**The mistake:** Using `black_home_zip_pct` from the Treasury dataset as a proxy for Black student enrollment share.

**Why it breaks:** These are ecological measures of the neighborhoods students come from, not student-level demographics. A student from a predominantly Black ZIP code is not necessarily Black, and the composition of home ZIPs tells you about where aid recipients grew up, not the student body composition.

**Detection:** Variable names containing `_home_zip_` are neighborhood-level measures.

**Avoidance:** Use IPEDS enrollment data for student-level racial demographics.

### Pitfall 5: Assuming Earnings Data Represents All Students

**The mistake:** Claiming "graduates of Institution X earn $Y" without qualifying that this covers only Title IV recipients who are working and not enrolled.

**Why it breaks:** At selective private institutions, Scorecard covers only 30-50% of students. The excluded students (full-pay, international) likely have different outcomes. Earnings also exclude self-employed, graduate school attendees, and non-workers.

**Detection:** Check institution-level Title IV coverage by comparing FAFSA applicant counts to IPEDS enrollment.

**Avoidance:** Always qualify: "Among Title IV aid recipients who were working and not enrolled in further education..."

### Pitfall 6: Comparing Scorecard Completion Rates to IPEDS Graduation Rates

**The mistake:** Treating Scorecard completion metrics and IPEDS graduation rates as interchangeable.

**Why it breaks:** Different populations (Title IV recipients vs. first-time full-time), different tracking methods (NSLDS system-wide vs. single institution), different inclusion of part-time and transfer students.

**Detection:** If you are joining Scorecard completion to IPEDS graduation rates, you are comparing apples to oranges.

**Avoidance:** Pick one source for graduation/completion rates and use it consistently. For this analysis, IPEDS graduation rates are the standard and more appropriate choice.

### 3. Population Coverage Bias Assessment

The Title IV limitation is the single most consequential caveat for this analysis. The bias is not random -- it is *systematically correlated with selectivity*:

**At highly selective institutions (admission rate <20%):** Title IV coverage is typically 30-50%. The excluded 50-70% are disproportionately: full-pay students from high-income families, international students, students with only institutional/private aid. These excluded students likely have higher family resources, different demographic profiles, and potentially different graduation trajectories.

**At moderately selective institutions (admission rate 40-60%):** Coverage is 60-75%. The bias exists but is smaller.

**At open-access institutions (admission rate >80%):** Coverage is 70-90%+. Scorecard data is reasonably representative.

**Net effect on this analysis:** If we used Scorecard demographics to measure "student body composition" across the selectivity spectrum, we would be measuring *different fractions of the student body* at each selectivity level. At selective schools, we would see a sample skewed toward lower-income students; at open-access schools, we would see nearly the full student body. This creates a systematic confound between selectivity and the population being measured -- exactly the confound this analysis needs to avoid.

**Recommendation:** Use IPEDS, which reports for the full student body regardless of aid status.

### 4. Earnings Data Assessment

**Can earnings serve as an alternative outcome?** In principle, yes -- post-graduation earnings complement graduation rates as a measure of institutional "quality" or "value added." However, for this specific analysis, the practical obstacles are significant:

**Bottom line:** Earnings data could be a compelling secondary analysis but should not be part of the core graduation-rate/selectivity analysis due to coverage bias, staleness, and the compounding population filters. If pursued later, it requires extensive documentation of limitations.

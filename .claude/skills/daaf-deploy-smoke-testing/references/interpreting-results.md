# Interpreting Deployment Smoke Results

Probe-by-probe interpretation for the DAAF deployment smoke suite: what each verdict means, which signals are expected mechanics rather than defects, route-conditional expectations, and how to route a real failure to its documented fix. Read this alongside a `report.md` from `scripts/deploy_smoke/reports/{local timestamp}_{stated route}/`, or from an imported package under `scripts/deploy_smoke/inbox/<package>/`. Each probe row below is what the report's problems table points to when a probe has no more specific fix location. Thresholds and match strings that have not yet been seen on a live run are listed at the end.

## Verdict Semantics

| Verdict | Meaning | Affects exit code? |
|---------|---------|--------------------|
| **PASS** | The probe's machinery worked as expected. | no |
| **FAIL** | A real defect for this route. Fix before trusting the deployment. | **yes** (nonzero) |
| **WARN** | Something worth a look, but not necessarily broken. Often expected on short headless runs (see below). | no |
| **SKIP** | Not applicable to the detected route (e.g. shim `/health` on a non-shim route). Correct behavior. | no |
| **INFO** | Informational context (e.g. the model-family/ceiling-hook posture), not a pass/fail signal. | no |

Only **FAIL** flips the overall verdict, matching the `run_all_smoke_tests.sh` contract. When triaging a report, read every FAIL first, then scan WARNs against the "expected mechanics" notes below before treating one as a defect.

The suite is **capability-structural**: Tier 1–2 probes check whether the machinery worked (did a subagent dispatch, did a script run, did a Skill load), *not* whether the model followed DAAF's protocols with high fidelity. Adherence quality is DAAFBench's job. A probe that PASSes confirms the plumbing is intact, not that the model behaves ideally. Tiers A and 3 come closest to behavior (Auto mode, the mode gate, skill retrieval); read their transcripts before treating a FAIL there as a deployment defect.

**Synthetic records.** Six probe IDs are written by the runner rather than a probe: `T0.ABORT` (FAIL: T0.0 failed, so no live tier ran), `T<tier>.CRASH` (FAIL: that tier raised an exception; the evidence holds the last 40 traceback lines, and the fix is in `scripts/deploy_smoke/`, not the install), `POST.CRASH` (FAIL: the post-run shim-log scan raised an exception, same reading), `RUN.CRASH` (FAIL: the whole tier block was interrupted, e.g. by Ctrl+C; the report and package still cover the probes that ran), `T<tier>.UNAVAILABLE` (SKIP: the checkout has no entry point for Tier N, A or 3) and `POST.UNAVAILABLE` (SKIP: the checkout has no `probe_shim_log_scan`).

## Reading a Report: the Diagnosis Summary

`report.md` opens with a Diagnosis summary written for the main session that will fix things:

1. **Identity block.** Stated and detected route (a `MISMATCH` here is the T0.1 FAIL), DAAF branch, `git describe --dirty`, SHA and dirty-file count, Claude Code version, shim version (shim routes, from T0.8's `/health`), Codex CLI version, the model mapping as configured, tiers and profiles, start and end time (UTC), paid calls and cost, and the overall verdict with counts. The versions come from `smoke_probes.collect_versions`, the same source as T0.15, so the dirty count matches T0.15's: it covers tracked **and untracked** files (`git status --porcelain`; `versions.daaf_dirty_files` and `versions.daaf_dirty_scope` in `report.json`). Paid calls are counted per `claude -p` invocation, so T3.1 and the T3.2 call that resumes its session count as two. Cost is the sum of what those invoking probes report, or T1.7's `total_cost_usd` when none does; "not reported" means no probe captured a cost. When a run used `--resume` (Tier 3), the total is labelled an **upper bound** (`total_cost_is_upper_bound: true` in `report.json`): a resumed session's reported cost may include the earlier call's cost, so the sum could count T3.1 twice. That cumulative-cost behaviour is inferred, not observed.
2. **Problems table**, every FAIL then every WARN, one row each. Columns: *Probe* (ID, profile, name); *Verdict*; *Observed* (the probe's detail, cut to 200 characters); *Likely cause* (the probe's hint, a static text per probe in `smoke_probes.PROBE_HINTS` / `route_detection.ROUTE_PROBE_HINTS`, or a shape-specific hint such as T0.8's stale-daemon text); *Evidence in package* (`report.md § <probe>`, the probe session's `transcripts/<sid8>/` folder, the packaged log for log-based probes, and any report-relative evidence file the probe names); *Where to fix* (a file, doc or action from the runner's location map, or this file's row for the probe). The log-based probes point at `logs/shim.log` (T0.8, T0.18, T0.20, TA.1) and `logs/codex_config.log` (T0.18). In the **packaged** `report.md`, an evidence path the zip does not hold is marked `(withheld)` (the post-scrub or names gate removed it) or `(not in package)` (never staged: not found, excluded, off-route or past the size cap).
3. **Passed** line: PASS count out of the probes run, per tier (plus a **Post-run** entry when the post-run scan ran), with SKIP and INFO counts.

The fingerprint table and full per-probe detail follow, each live probe with its duration, session ID prefix and cost, and a **Hint** line on FAIL and WARN. The report writer strips raw ANSI escape sequences and control characters from every name, detail, hint and evidence block; the statusline probes (T0.7, T1.6) also strip the escaped text forms before quoting (see T0.7). `report.json` (schema version 2) carries the same data plus `started_utc`, `ended_utc`, `stated_route`, `versions{}`, `paid_calls`, `total_cost_usd`, `total_cost_is_upper_bound`, and per probe `tier` (`post` for the post-run scan), `duration_s`, `session_ids`, `cost_usd` and `hint`.

> **Tier 0 limitation — ambient env only.** Tier 0 runs **once**, against the ambient (as-launched) environment, before any profile overlay is applied. Its route/env-coherence and context-window checks (T0.1–T0.4) therefore describe the base installation, **not** any `--profiles` overlay. A profile that, say, sets `ANTHROPIC_MODEL` to a GLM slug and declares its window via `CLAUDE_CODE_MAX_CONTEXT_TOKENS` is exercised only in that profile's Tier 1/2 runs — Tier 0 never re-validates per-profile overlays. Separately, before paid Tier 1/2 launches the runner repeats **only main-model coherence** for each actual child environment (including when Tier 0 is omitted). Known incompatibility blocks that profile, not compatible siblings; unresolved/WARN preserves ordinary exit behavior. When multi-profiling, read each profile's overlay in `profiles.yaml` directly to confirm its window/remap declarations; the Tier 0 verdict speaks to the ambient config alone.

## Tier 1 — One Live Round-Trip

A single cold-start `claude -p` call plus the plumbing checks around it. Three of these probes often report **INFO** on a healthy install: T1.4 and T1.5 because of short-headless-run mechanics, and T1.9 because the Tier 1 prompt forbids every tool but one Bash call. That is expected, not an install defect, and knowing why prevents false alarms.

**Live-run health gate.** Before judging anything, the suite checks whether a real model actually answered. A `claude -p` run can exit cleanly while no model ran. With an unknown model slug, an exhausted spend cap, or an API error, the CLI writes a local assistant record: `message.model` is `<synthetic>`, `isApiErrorMessage` is `true`, and `error` is `"model_not_found"` (observed 2026-09-24). That record's error sentence then comes back as the "response". The gate fails the run if any of these hold:

- the CLI result has `is_error: true`, a `subtype` other than `"success"` (except `"error_max_turns"`, below), or a non-null `api_error_status`. Every `api_error_status` seen so far has been null, so treating a non-null value as an API failure is inferred, and the reason says so;
- the transcript **ends** on an API-error record: some assistant record has `isApiErrorMessage: true` or an angle-bracketed placeholder model, and no real-model assistant record follows the last such record;
- `modelUsage` names no real model;
- the run timed out or the CLI errored.

T1.1, T1.7 and every Tier 2 probe then FAIL with that reason. T1.5 and T1.6 SKIP, since there is no real session to judge.

Two conditions are a **WARN** instead, because a real model did answer. In both cases the probe still judges its own evidence, and a PASS becomes WARN with the reason appended as "Live-run warning: …". This applies to T1.1 and every Tier 2 probe.

- **A recovered transient error.** A mid-response provider error is written as the same kind of `<synthetic>` record (`error: "server_error"`, text "API Error: Server error mid-response. The response above may be incomplete."). The CLI then retries. The observed pattern is real record → error record → real record, in about 20 headless transcripts on the GPT lanes. The warning gives the number of error records and the first one's error and text, truncated. If no real record follows the **last** error record, the run ended on the error, and that is a FAIL.
- **A `--max-turns` stop.** CLI result `subtype: "error_max_turns"`. The run hit its turn limit before finishing, so a missing completion token or marker FAILs on the probe's own check, with the max-turns note attached. The exact shape of this result object (for example whether `is_error` is also true) has not been observed in this repo, so the gate accepts either value.

## Tier 2 — Seven-Probe Functional Battery

Each probe is a separate cold-start run. All checks are capability-structural and deliberately tolerant of stylistic/protocol variation. Each probe first applies the Tier 1 **live-run health gate**. A run where no real model answered (a transcript that ends on a `<synthetic>`/API-error stub, `is_error`, a non-`success` subtype, a non-null `api_error_status`, or an empty `modelUsage`) is a **FAIL** that names the reason, never a PASS or a vacuous SKIP. A recovered transient error, or a stop at `--max-turns` (subtype `error_max_turns`), is not a gate FAIL. The probe judges its own evidence, and a PASS becomes WARN with the reason (see the Tier 1 gate above).

Every Tier 2 run works inside its own **per-run, UUID-owned sandbox** — `scripts/deploy_smoke/_sandbox/run_<uuid>/`, created fresh at the start of the run and removed in a guaranteed cleanup path (scoped to exactly that directory — never a recursive wipe of `_sandbox/` and never a sibling). This is what makes the T2.1/T2.2 fixtures fresh *by construction*: a run directory left behind by a hard process kill carries a UUID no future run mints, so it is inert crash residue that cannot satisfy a later run. The two historical root-level fixtures (`_sandbox/t21_marker.txt`, `_sandbox/t22_probe.py`) predate this design and are non-authoritative; all of `_sandbox/` stays git-ignored.

## Tier D — Deterministic Battery (zero API cost)

Selected with `D` in `--tiers` (with `--include-r-smoke` for TD.6, `--tier-d-all` for TD.7 off the shim routes). It runs after every other tier. Every probe shells a repo test entry point and reports its exit code — no LLM, no cost. A missing tool is a **SKIP**, not a FAIL, so running Tier D outside the `DAAF_DEV=1` image degrades gracefully rather than failing spuriously.

**The harness self-tests itself first.** TD.0 discovers `tests/python/test_deploy_smoke*.py` *before* the broader batteries. This includes the existing harness contracts plus shared main-model preflight. These are provider-free contract tests, not live provider acceptance. For agent execution, use a fresh flat audited launcher with `unittest.defaultTestLoader.discover('/daaf/tests/python', pattern='test_deploy_smoke*.py')`, `sys.dont_write_bytecode=True`, and an assertion on `TextTestRunner(...).run(suite).wasSuccessful()`, executed through `run_with_capture.sh`.

**Deterministic environment isolation.** All Tier D subprocesses run under a sanitized copy of the live environment with exactly two variables stripped — `CLAUDE_CODE_MAX_CONTEXT_TOKENS` and `DAAF_BRANCH` — because a fully-configured live install legitimately exports both, and both steer default-window / default-branch fixtures onto the live session's values. This is defense-in-depth *atop* each battery's own fixture isolation (bats `setup()` unset, Pester `BeforeEach` removal), **not** `env -i`: `PATH`, `HOME`, route credentials, and the developer toolchain are all preserved so the batteries can still find their interpreters. TD.0's evidence records which variables were actually removed.

**Two-level evidence policy.** On a **PASS**, a probe keeps only a concise final excerpt (the last several lines) in the report. On a **FAIL or timeout**, the report quotes a bounded head-and-tail excerpt (so both the earliest failure names and the final summary stay visible) *and* the COMPLETE scrubbed output is persisted to `evidence/tier_d/{probe_id}.log`, referenced from the probe's evidence. All captured output is scrubbed for secret env values before it is quoted or persisted.

|-------|-----------|--------------------------|

## Post-run — Shim-Log Verdict for This Run (shim routes)

On a shim route (judged by the **stated** route; a detection mismatch is already T0.1's FAIL), after the live tiers and only when a live tier (1, 2, A or 3) actually ran, the runner scans `scripts/provider_shim/logs/shim.log` again, from the run start (container-local time, the shim's own timestamp format) to the end of the log. This scan carries the shim-log verdict; Tier 0's T0.20 only reports the earlier history, as INFO. It appears in `report.md` as its own **Post-run** section (after every tier section of the per-probe detail), with `tier: "post"` in `report.json` and a Post-run entry on the Passed line. A Tier-0-only, N-only or D-only run has no Post-run section. In `MATRIX.md` the two T0.20 results share one row, so a shim column reads `INFO/<post-run verdict>`.

| Probe | PASS means | FAIL / WARN interpretation |
|-------|-----------|----------------------------|
| **T0.20 Shim-log scan (post-run window)** | Counts only, never line text: no failure signal in this run's window. Recovered whitespace retries (`retry_reason=tool_argument_whitespace outcome=success`) are reported as INFO inside the detail. A `shim vX starting` line before the window resets the counters (the scan covers the daemon serving the run); a start **inside** the window, a mid-run restart, does not: the counts accumulate across it, `daemon_restarts_in_window` in the evidence counts it, and the detail adds "Daemon restarts inside the window: N". | **FAIL** = `x-codex-turn-state` lines written during the run (header leakage; shim 1.4.9 stops it; F28), or `insufficient_quota` (an unfunded API key or a spending cap; F22; the counter keeps that name but counts any of the six quota codes the shim classifies: `insufficient_quota`, `usage_not_included`, and since 1.4.11 `credit_balance_exhausted`, `organization_spend_limit_exceeded`, `project_spend_limit_exceeded`, `organization_usage_limit_exceeded`). **WARN** = Claude-slug fast-fails or Claude-named requests (map all aliases, T0.17; F2), unrecovered whitespace trips (`attempts=1 backend_code=excessive_json_whitespace`; F17), `unsupported_value` (for example a `#none` effort; F15) or `context_length_exceeded` (a request over the context ceiling; shim 1.4.10 stops sending the non-streaming in-band case as a 502, and from 1.4.11 the user should see Claude Code's "Prompt is too long" / "Context limit reached" notice (read from client source, not yet seen live); F21, F32); also WARN when the log could not be read. Evidence in the package: `logs/shim.log`, the run window. Read the log around the signal without pasting header lines. |

`POST.CRASH` (FAIL) and `POST.UNAVAILABLE` (SKIP) are the synthetic records for a scan that raised an exception or does not exist in the checkout (see Verdict Semantics).

## Route-Conditional Expectations and Known Failure Modes

Each route has a distinct configuration surface. Below: what Tier 0 expects for the route, and the known failure modes (with their documented fixes) that a live-tier FAIL most likely maps to.

### anthropic-subscription (native, no shim)

- **Expected:** No `DAAF_PROVIDER_SHIM`, no OpenRouter base URL. The session model resolves from `ANTHROPIC_MODEL` if set, else a saved `/model` choice, else the soft default `ANTHROPIC_DEFAULT_MODEL` that `settings.json` ships (`opus`, Claude Code's built-in Opus when unmapped). A Claude Enterprise organization default, if set, is not modeled. T0.3 records both start selectors; `ANTHROPIC_MODEL` is normally `<unset>`. `enforce-model-ceiling.sh` actively **ranks** subagent dispatches (haiku < sonnet < opus < fable). T0.2 should report family `claude`, `remap_active=false`.
- **Auth:** Interactive OAuth or `CLAUDE_CODE_OAUTH_TOKEN`. Tier 0 cannot verify interactive OAuth without an LLM call, so a genuine auth problem surfaces at **T1.1** (round-trip fails), and T1.8 confirms the credential in use (`apiKeySource` `none`). `ANTHROPIC_API_KEY` must be empty or unset: a non-empty key makes the install detect as `anthropic-api`, and T0.16 FAILs a stated subscription run because every `-p` probe would bill the key.
- **Known failure mode:** `ANTHROPIC_BASE_URL` unexpectedly set while the route detects as native — T0.3 flags it. Unset it for the native route. A stray `ANTHROPIC_AUTH_TOKEN` outranks the login (T0.3 and T0.16 FAIL).

### anthropic-api (native, Console API key)

- **Expected:** the same endpoint, model resolution and ceiling-hook posture as the subscription route, with a non-empty `ANTHROPIC_API_KEY` as the credential. T1.8 expects a paid `apiKeySource` (`ANTHROPIC_API_KEY`, `/login managed key` or `apiKeyHelper`). A `CLAUDE_CODE_OAUTH_TOKEN` alongside is unused overlap (T0.16 WARN).
- **Spend:** every live probe bills the key, and each call carries `--max-budget-usd` ($2 for Tier 1, $5 per Tier 2 call, $2 for Tier A, $3 per Tier 3 call). T1.7 labels its cost as real spend. A call that hits its cap ends with a non-success result, and the live-run gate FAILs with that reason.
- **Known failure modes:** an unfunded or revoked key fails at T1.1; `ANTHROPIC_AUTH_TOKEN` set outranks the key (T0.16 FAIL).

### openrouter

- **Expected:** `ANTHROPIC_BASE_URL` ends with `openrouter.ai/api`; `ANTHROPIC_AUTH_TOKEN` set (your OpenRouter key, Bearer auth); `ANTHROPIC_API_KEY` **present-and-empty** (`ANTHROPIC_API_KEY=`) so the `X-Api-Key` header does not override Bearer auth. For non-Claude models, map all four tier aliases: the `ANTHROPIC_DEFAULT_OPUS_MODEL`/`SONNET_MODEL` remap keeps subagents pure and makes the ceiling hook **stand down**; `ANTHROPIC_DEFAULT_HAIKU_MODEL` carries Claude Code's housekeeping calls (naming and summarizing the session). Left unmapped, Claude Code has sent these as Claude Haiku requests that the route rejects (July 2026 shim logs); Claude Code's current docs say they run on the main, pricier model. `ANTHROPIC_DEFAULT_FABLE_MODEL` covers the `fable` alias. T0.4 checks every mapped slot's window. `CLAUDE_CODE_SUBAGENT_MODEL` alone does not reroute DAAF agents (a fallback only since Claude Code 2.1.251; `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` forces it). `CLAUDE_CODE_MAX_CONTEXT_TOKENS` declares the real window.
- **Known failure modes (documented in `user_reference/01_installation_and_quickstart.md` § "Setup Troubleshooting", anchor `#setup-troubleshooting`):**
  - *"model not found" / auth errors* — three causes: wrong base-URL suffix, `ANTHROPIC_API_KEY` unset vs. empty, or a stale login needing `/logout`. T0.3 catches the base-URL and empty-key cases directly.
  - *`-pro` GPT slugs* — the July 2026 hard "Prompt is too long" wall (~200k reported tokens) did not reproduce in the 2026-09-29 retest (more than 930k reported tokens accepted; `research/2026-09-29_FrameworkDev_OpenRouterDottedModelNames/preliminary_notes/2026-09-29_openrouter-pro-retest.md`). A `-pro` "Prompt is too long" at low utilization is therefore no longer an expected known cause; check the window declaration (T0.4) first. The ~3–4x inflated token accounting persists, so `-pro` runs cost several times more and DAAF's context warnings fire earlier in real content terms (`01_installation_and_quickstart.md` § "GPT (OpenAI) models via OpenRouter (Option C, extended)", anchor `#gpt-openai-models-via-openrouter-option-c-extended`). Prefer a standard flagship slug for cost reasons.
  - *Ceiling-hook DENY on a non-Claude session* — if a non-Claude family is configured **without** an OPUS/SONNET remap, a Claude-tier subagent request is denied with remap guidance (`enforce-model-ceiling.sh` rule f). A per-dispatch `model` cannot fix it (the parameter accepts only Claude aliases); set the `ANTHROPIC_DEFAULT_*` remap vars for all four tiers. T0.2's INFO posture is the early warning. `CLAUDE_CODE_SUBAGENT_MODEL` alone no longer stands the hook down, and the deny message names the four `ANTHROPIC_DEFAULT_*_MODEL` settings, not that variable (hook updated 2026-10-12; an older installed hook still stands down for it, and T0.2 says when that hook is the one installed).
  - *Context under-reporting* — a GPT/non-`[1m]` slug without a window declaration → T0.4 FAIL.

### chatgpt-subscription and openai-api (shim)

- **Expected:** `DAAF_PROVIDER_SHIM=openai`; `ANTHROPIC_BASE_URL` → `http://127.0.0.1:4141`; `ANTHROPIC_AUTH_TOKEN=daaf-shim-local`; `CLAUDE_CODE_DISABLE_FAST_MODE` exactly `1` (T0.3 FAILs otherwise; `bash /daaf/scripts/provider_shim/gpt_fast.sh off` keeps the requested service-tier policy off). The ChatGPT lane additionally needs `SHIM_BACKEND_MODE=chatgpt` and `CODEX_HOME` (holds `auth.json`); the API lane needs `SHIM_BACKEND_MODE=openai` and `OPENAI_API_KEY` or `SHIM_BACKEND_API_KEY`. T0.8 shim `/health` must report the matching `backend_mode`, a `version` equal to the source on disk, and a valid `gpt_service_tier` block. All four tier aliases must map to GPT models (T0.17), Claude Code must be 2.1.276 or later (T0.15), and TD.7 runs the shim unit suite by default.
- **Daemon state is not per-run overridable.** `SHIM_SANITIZE_TOOLS` and `backend_mode` are fixed at shim startup; `--profiles` overlays reach only the CLI session, so the runner WARNs if `--profiles` is used on a shim route. Verify daemon state read-only via T0.8.
- **Known failure modes:**
  - *ChatGPT-lane auth* — `codex_home_present=false`, or T0.9 FAIL (WARN while it is only expiring) → `auth.json` missing, unreadable or expired; run `codex login --device-auth`. Token refresh is JWT-`exp`-based and lazy; a genuinely expired, un-refreshable token surfaces at T1.1.
  - *GPT tool-call quirks* — `isolation`-fill hangs and empty `Read.pages` are handled by the shim's `_sanitize_tools` (default on, both shim routes) and, for `isolation`, by `block-remote-isolation.sh` at the hook layer. T2.5 exercises the hook-layer strip. For DAAFBench raw-model runs `SHIM_SANITIZE_TOOLS=0` is required — but that is a benchmark concern, not a deployment-health one.
  - *API-lane instant 429* — an unfunded OpenAI API key returns 429 immediately (distinct from a ChatGPT subscription); surfaces at T1.1, and the post-run T0.20 scan FAILs on the `insufficient_quota` log lines. Fund the API account or switch to the chatgpt route (`07_faq_technical.md` § "Q: My GPT session fails instantly with 429 errors on every request (Option F)", anchor `#q-my-gpt-session-fails-instantly-with-429-errors-on-every-request-option-f`).
  - *ChatGPT lane is an unofficial dev lane* — explicitly flagged as not OpenAI-sanctioned and liable to break (`01_installation_and_quickstart.md` § "Option F, alternate lane: ChatGPT subscription (Codex backend)", anchor `#option-f-alternate-lane-chatgpt-subscription-codex-backend`); a sudden T1.1 failure here may be upstream, not a local misconfig.

## Auto mode

Tiers 1, 2 and 3 use `bypassPermissions`, so they never exercise Auto mode's classifier; Tier A (TA.1) does, with one `--permission-mode auto` call. The notes below explain what TA.1 sees and what an interactive session shows.

- **Working:** allowed actions run with **no permission prompt**. That is the point of Auto mode, so no pop-ups is the expected result. The status bar shows "auto mode on". Explicit ask rules (for example DAAF's `git push`) still prompt.
- **Denied:** Claude Code shows a notification, and the action appears in `/permissions` under *Recently denied*. Three denials in a row, or 20 in total, pause Auto mode and bring prompts back.
- **Classifier failure:** a message saying Auto mode "cannot determine the safety" of an action, with no *Recently denied* entry.
- **On shim routes:**
  - Claude Code cannot use Anthropic's server-side review (the `safeguards` pass-through), because the shim's upstream is OpenAI. It falls back to its own classifier requests, which go through the shim to the GPT model. In `shim.log`, a request line containing `stream=n msgs=<N> tools=0` is likely a classifier request, and TA.1 counts successful terminals of that shape. Treat that as a heuristic: other non-streaming, tool-less housekeeping calls share the pattern. The report fingerprint records `CLAUDE_CODE_AUTO_MODE_SERVER`.
  - Claude Code announces that fallback with a notice that "this session isn't eligible" for the new classifier billing. On the pinned Claude Code version (2.1.281) the notice is harmless. Set `CLAUDE_CODE_AUTO_MODE_SERVER=0` (see the env template) to skip the server request and the notice.
  - After the first reply, `/status` shows "Auto mode server: Disabled". That is expected on these routes.
- **Upgrade gate:** a third party (LiteLLM, October 2026) reports that Anthropic told them Claude Code releases after 2026-10-23 support only server-side Auto mode, which is unavailable behind a gateway that doesn't support it; the shim never can. Anthropic's docs do not say so yet. If it holds, Auto mode stops working on GPT routes after such an update, and `CLAUDE_CODE_AUTO_MODE_SERVER=0` will not restore it. Before bumping the pinned Claude Code version (2.1.281), run Tier A on a shim route and require TA.1 to PASS.

## The Package: MANIFEST, Scrub Counts, Excluded and Withheld

Every package carries `MANIFEST.json` (`kind: daaf-smoke-package`, `schema_version` 1, `tool_version` from `smoke_package.TOOL_VERSION`, currently `1.2.0`, bumped whenever a field, a package path or an import rule changes; 1.0.0 packages lack `truncated_reads`, `size` and the newer scrub keys, and packages before 1.2.0 lack `truncated_lines` and dropped whole `| headers:` lines and Codex-header lines in the reports). Read it when something you expected is missing, or before trusting that a file is clean.

**Package name.** `daaf-smoke_<UTC yyyymmddThhmmssZ>_<stated route>_<sha7>.zip`. `<sha7>` is `nosha` when git gave no usable SHA, and a route token that is not a plain route name becomes `unknown-route`. When a package of the same name already exists (two runs in the same UTC second), the packager adds `_2`, `_3`, … before `.zip`; the importer and `MATRIX.md` accept the suffix, and same-route matrix columns show it.

| Field | Meaning |
|-------|---------|
| `package`, `created_utc`, `route`, `detected_route` | The file name, build time, stated route and detected route |
| `run` | `started_utc`, `ended_utc`, the report folder name, `overall` and the verdict counts |
| `versions` | The identity block: DAAF branch, SHA, describe, dirty-file count (`daaf_dirty_files`, tracked and untracked; `daaf_dirty_scope` says so), Claude Code and its pin, Codex, shim and shim source, Python, and `source` (which collector produced the block) |
| `session_ids` | The probe sessions whose transcripts and audit rows were packaged |
| `secret_vocab_source` | `web_retrieval_common` when the shared secret-name vocabulary loaded, `mirror` when the packager used its built-in copy |
| `files[]` | Every packaged file: `path`, `sha256`, `bytes`, `source` (where it came from, with the cut applied, e.g. "run window") and non-zero `scrub_counts` |
| `scrub_totals` | The same counts summed over the package |
| `excluded[]` | Sources deliberately not packaged, each with a `reason` |
| `withheld[]` | Files that were staged and then removed, each with a `reason` |
| `truncated_reads[]` | Logs read from the end because they were larger than the read cap: `source`, `bytes_total`, `bytes_read` |
| `size` | `staged_bytes`, `cap_bytes` (256 MiB) and `cap_reached` |
| `gates` | `post_scrub_secret_scan` (`clean`, or how many files were withheld) and `names_only_invariants` (the `check_workspace_invariants.sh --names-only` result on the staging tree) |
| `manifest_self_scrub_counts` | Present only when scrubbing changed `MANIFEST.json` itself: the replacements made in it (for example `{"email": 1}` for an address in a version string) |

**Scrub counts** (per file and in total) say how many replacements each rule made. Every staged file is scrubbed, including files that are not valid UTF-8: they are decoded with `surrogateescape`, so their undecodable bytes pass through unchanged while text patterns are still replaced.

| Key | What was replaced |
|-----|-------------------|
| `truncated_lines` | `logs/shim.log` only: lines cut at their `\| headers:` dump. The shim writes its backend-error and retry records as `… backend 400 (attempt 1/3) … \| headers: {…}`; the record up to the dump is kept and the dump becomes `\| headers: [REMOVED]`. Cutting runs before the line drops, so a dump holding a Codex header no longer costs the record |
| `dropped_lines` | Copied logs and transcripts only: whole lines dropped because they carried `x-codex-turn-state` or `x-codex-credits`. Generated files (`report.md`, `report.json`, the README, `MANIFEST.json`, the settings and quota projections) are never line-dropped: a dropped line would delete a report row or break the JSON. In them a Codex header **with a value** has the value replaced in place (`x-codex-turn-state: [REDACTED:header]`, counted under `secret_header`), and a text that only names the header is kept |
| `env_value` | The live value of a credential-named environment variable (raw or JSON-escaped), replaced with `[REDACTED: value of NAME]` or `<redacted:NAME>` |
| `private_key` | PEM private keys: a whole `-----BEGIN … PRIVATE KEY-----` to `-----END … PRIVATE KEY-----` block, or an orphan BEGIN line with the base64 body after it (a block cut by truncation; raw or JSON-escaped newlines) → `[REDACTED:private-key]` |
| `jwt` | JWT-shaped tokens (`eyJ…`) → `[REDACTED:jwt]` |
| `sk_key` | `sk-`/`rk-` style keys → `[REDACTED:sk-key]` |
| `bearer` | `Bearer <token>` → `[REDACTED:bearer]`, and `Authorization: Basic <credentials>` → `[REDACTED:basic]` |
| `secret_header` | Values of `x-api-key`, `api-key` and `proxy-authorization` → `[REDACTED:header]`; an `Authorization` or `Proxy-Authorization` value with any other scheme or none (a bare token) → `[REDACTED:authorization]`; a Codex turn-state or credits header value in a generated file → `[REDACTED:header]`; and **every** value in a `Cookie` / `Set-Cookie` header, however short (`Cookie: a=1; sid=…` → `Cookie: a=[REDACTED:cookie]; sid=[REDACTED:cookie]`; the names and the `HttpOnly` / `Secure` / `Partitioned` flags are kept, one per redacted value counted). Both the raw form and the JSON-escaped form inside a JSONL string (`\"Authorization\": \"…\"`) match |
| `userinfo` | URL credentials, `scheme://user:password@host` → `scheme://user:[REDACTED:userinfo]@host`, for any host including undotted ones such as `localhost` |
| `url_param` | Secret URL query values, `?key=…` / `&key=…` → `key=[REDACTED:url-param]`, when the key is in the secret vocabulary (hyphens read as underscores) or a signed-URL name (`sig`, `signature`, `code`, `x-amz-signature`, `x-amz-credential`, `x-goog-signature`, `x-goog-credential`, `client_secret`). Non-secret keys such as `api-version` are kept |
| `credits` | The shim's `credits_*` account fields (`credits_has`, `credits_balance`, `credits_unlimited`, …) in `key=value` or `"key": value` form → `credits_<key>=[REDACTED]`, key name kept, in every file, including the per-request quota lines in `logs/shim.log` |
| `email` | Email addresses → `[REDACTED:email]` |
| `secret_assignment` | `NAME=value` or `"name": "value"` where the name is in the secret vocabulary. Kept as diagnostic: session IDs, token counts, `session_model`, the shim's `request_shape` key lists (`keys`, `text_keys`, `reasoning_keys`; key names only), `auth_mode`, `prompt_cache_key`, `cache_key` and the manifest's `secret_vocab_source` (`smoke_package.NON_SECRET_NAMES`, each checked against its writer). `auth_status` and `key_source` stay redacted: no writer was found to check them against. A value may contain balanced `[…]` groups, so a model ID such as `gpt-6.1-sol[1m]#high` is read as one value, never cut at `]` |

A high `email` or `secret_assignment` count in a transcript usually means the model quoted configuration or a user address; it is not by itself a leak, since the values were replaced. Placeholders such as `<redacted:set>` in the fingerprint and settings projection come from the report's own name-based redaction.

**The post-scrub gate** re-scans every staged file with the same shapes the scrubber applies (PEM BEGIN lines, JWTs, `sk-`/`rk-` keys, Bearer, Basic, the named headers, Authorization, URL userinfo, secret URL parameters, `credits_*` values, emails, secret-vocabulary assignments), plus Cookie values, any leftover `x-codex-turn-state` / `x-codex-credits` text in a copied log or transcript (in a generated file, only such a header with an unredacted value), and any live credential env value. A generated JSON file that scrubbing changed must still parse; if it does not, it is withheld as `withheld: generated JSON no longer parses after scrubbing (…)`. None of those patterns matches the scrubber's own `[REDACTED…]` markers or route_detection's `<redacted…>` markers, so a scrubbed file does not trip the gate on its own replacements.

**Size and read caps.** A copied file over 64 MiB (`MAX_SOURCE_FILE_BYTES`) is excluded as too large. The three growing logs are not excluded but read **from the end**, at most 64 MiB each, before they are cut: `shim.log` (then the run window), `codex_config.log` (then its last 200 lines) and `activity.log` (then the run window, at most its last 2000 lines). A log larger than the cap is listed in `truncated_reads`. The staged package as a whole is capped at 256 MiB (`MAX_PACKAGE_TOTAL_BYTES`): files past the cap are excluded with the reason "package size cap reached", the run prints a WARN, and `size.cap_reached` is true. The generated README is exempt from the cap.

**Excluded** sources are policy, recorded so the reader knows they were deliberate: `$CODEX_HOME/auth.json`, `~/.claude/.credentials.json` and `.claude.json`, the shim reasoning cache, `scripts/provider_shim/logs/diagnostics/`, the bulk session archive (only probe sessions are packaged), rotated `shim.log.[1-3]`, the `shim.stream.*` FIFOs, any file whose name marks credential material (any name starting with `.env`, `*.pem`, `*.key`, `credentials*`, `secrets`, `environment_settings*`, SSH keys), non-regular files (symlinks, FIFOs, sockets), files over 64 MiB, files past the package size cap, and sources that were simply not present (for example no transcript found, or no shim log off the shim routes).

**Withheld** files were staged and then removed: `withheld: secret-shaped content (<kinds>)` when the post-scrub gate still found a secret shape after scrubbing (the run prints a WARN naming the file), a name Windows cannot create or a case-only clash, a duplicate package path, or a name that failed `--names-only`. If the names check still fails after those removals, no package is written at all. A withheld transcript is the usual case: open the original on the test container if the evidence matters, and never copy it out unscrubbed.

**README and report annotations.** `README_FOR_MAIN_SESSION.md` is generated **after** both gates. Its **"Not in this package"** section lists the withheld files with their reasons (or "none"), the sources not found when the package was built, the logs read from the end only (bytes read of bytes total), and whether the size cap was reached; it then points to `MANIFEST.json` for every exclusion. The README is scrubbed and gate-checked like any file; if a listed path or reason trips a pattern, it is regenerated as static text, which is scrubbed and gate-checked again, and if that also fails the README is withheld (reason "full and static forms", with a WARN). `MANIFEST.json` is written last, after every other file is final, and is itself scrubbed and gate-checked; it never hashes itself, so scrubbing it cannot break a file hash. If scrubbing would change its file list, leave it unparseable or unstable, or the gate still finds a secret shape in it, no package is written (the run prints the reason as a WARN). The packaged `report.md` is annotated at the same point: in its Problems table, an evidence path the zip does not hold is marked `(withheld)` or `(not in package)`.

**Importer checks** (`--import`): the file must be a regular `.zip` with a safe name; members must be regular files with safe relative names (no absolute paths, `..`, backslashes, NUL or Windows-incompatible names), each listed in `MANIFEST.json` and matching its sha256 and size; limits are 512 MiB per member and 1 GiB per package. Any failure rejects the whole package and keeps nothing. A corrupt or unreadable package is rejected the same way (`corrupt zip (…)` or `extraction failed (<error type>: …)`), and the importer goes on to the next package: one bad package never blocks the others.

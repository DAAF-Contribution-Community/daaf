# DAAF ENVIRONMENT SETTINGS
# ============================================================================
# HOW TO USE THIS FILE
#   1. Copy this file to environment_settings.txt in your daaf-docker folder:
#          cp environment_settings_example.txt environment_settings.txt          (macOS / Linux)
#          Copy-Item environment_settings_example.txt environment_settings.txt   (Windows PowerShell)
#   2. Turn a setting ON by deleting the single leading '#' on its "#KEY=value"
#      line, then fill in your value. The long "# ..." prose lines are
#      explanations -- leave those commented; only "#KEY=value" lines are meant
#      to be uncommented.
#   3. Apply your change. Most settings need a container recreate; a few need an
#      image rebuild, and a few must be set BEFORE install -- each section's
#      banner carries a lifecycle tag saying which (and the CONTENTS map below
#      summarizes them). The usual recreate is:
#          docker compose down
#          bash run_daaf.sh    (macOS / Linux)   |   .\run_daaf.ps1   (Windows)
#   Full walkthrough: user_reference/01_installation_and_quickstart.md
#
# CONVENTIONS USED BELOW
#   #KEY=value   An activatable example. Always flush at column 0 with the '#'
#                immediately in front of the key, never indented, and never with
#                a trailing "# ..." comment on the same line (a value followed by
#                an inline comment breaks some parsers). Delete the one leading
#                '#' to turn it on.
#   # text       An explanatory prose line (it may be indented AFTER the '#').
#   Write values bare: KEY=value with nothing extra -- no quotes around the
#   value and no spaces around the '='. DAAF's readers take the line literally,
#   so quotes or stray spaces can end up inside your value. (Editing on Windows
#   is fine -- Windows line endings are tolerated.)
#   Adjacent #KEY lines introduced with "pick ONE" are mutually exclusive
#   alternatives -- uncomment only the set for the method you chose.
#
# IMPORTANT: environment_settings.txt is gitignored by default. Never commit it
# and never paste real keys or tokens anywhere. This example file holds NO real
# values and sets NOTHING by default -- everything ships commented out, so a fresh
# copy is safe by default.

# ============================================================================
# [1] Install & Update Settings  (set BEFORE install/update)
# ============================================================================
# These DAAF_* settings are read by the host-side launcher and lifecycle scripts
# (install, update, run, backup, rebuild) on your OWN machine -- not only inside
# the container. Because the host scripts read them, they behave a little
# differently from the container-only keys in later sections:
#
#   * For a STANDARD single install, leave everything in this section unset --
#     the defaults reproduce the original behavior exactly.
#   * The multi-instance keys (DAAF_PROJECT_NAME, DAAF_PORT_*) only matter when
#     you run a SECOND DAAF install on the same machine.
#
# WHEN ARE THESE READ? At install time this file may not exist yet -- install is
# what CREATES it. So for a brand-new SECOND instance you set these as real
# environment variables BEFORE the first install/run (export them, or prefix the
# command). AFTER the install exists, this file becomes their permanent home and
# the host scripts read them from here.
#
# LIFECYCLE NUANCE: the section banner's "(set BEFORE install/update)" tag is
# strictly true only for DAAF_PROJECT_NAME, which is fixed at creation time --
# changing it on an existing install detaches it from its data volume. The PORT
# keys CAN be changed later: set the new value here, then recreate the container
# (docker compose down, then run_daaf.sh / run_daaf.ps1) per the header's recreate
# guidance. DAAF_BRANCH is likewise read on every update, so it too can change at
# any time.
#
# AUTO-SEEDING: at install time DAAF seeds this file for you from any DAAF_*
# environment variables you had set for the install -- so if you exported
# DAAF_PROJECT_NAME / DAAF_PORT_* / DAAF_BRANCH before installing a second
# instance, they are written here automatically and persist for later updates.
#
# ----------------------------------------------------------------------------
# Update channel: which branch DAAF updates track
# ----------------------------------------------------------------------------
# DAAF_BRANCH selects the git branch that update_daaf.sh (and the control panel's
# update option) pull from. It can live HERE -- persisted for every future update
# -- OR be exported / prefixed for a single update run, in which case the
# environment value wins for that one run:
#
#     DAAF_BRANCH=dev bash update_daaf.sh          (one-off; no export needed)
#
# DEFAULT: main (the stable release branch) when unset.
#
# A release TAG (e.g. v2.1.0) is NOT an update channel. The updater tracks
# BRANCHES only -- it follows a moving branch to pull ongoing changes, whereas a
# tag is a fixed snapshot with nowhere newer to advance to. Concretely:
#
#   * Set DAAF_BRANCH to a tag in your ENVIRONMENT and the updater declines with
#     an explanation and makes NO changes -- it neither silently no-ops nor locks
#     you out. To move an installation onto a specific release, do a FRESH INSTALL
#     pinned to the tag instead (the installer accepts a tag as DAAF_BRANCH).
#   * A tag accidentally written into THIS file is not fatal either: the updater
#     warns and falls back to the default branch for that run (no lockout).
#
# So persist a moving BRANCH name here, never a tag.
#
# --- To activate, remove the leading '#' and set your channel: ---
#DAAF_BRANCH=main
#
# ----------------------------------------------------------------------------
# Multi-instance: run more than one DAAF on the same machine
# ----------------------------------------------------------------------------
# Give each install folder its own project name and host ports so two instances
# never collide. All DAAF scripts read these automatically. Leave everything
# unset for a standard single install -- the defaults match the original behavior
# exactly.
#
# NOTE: if you run `docker compose` commands DIRECTLY (outside the provided
# scripts), also create a .env file in this folder with the same values -- bare
# docker compose does not read environment_settings.txt for these.
#
# Compose project name (prefixes the container and data volume). DEFAULT: daaf
# WARNING: changing this on an EXISTING install detaches it from its current data
# volume -- only set it when creating a NEW second install.
# --- To activate, remove the leading '#': ---
#DAAF_PROJECT_NAME=daaf2
#
# Host ports for the web services. DEFAULTS: 2718 / 2719 / 2720
# (These replace the old "hand-edit docker-compose.yml" method for port changes.)
# --- To activate, remove the leading '#' on the lines you need: ---
#DAAF_PORT_MARIMO=3718
#DAAF_PORT_LOGVIEWER=3719
#DAAF_PORT_VSCODE=3720
#
# Data-volume override (advanced; shared workspace across installs). Normally the
# research workspace lives in a Docker volume named "<project>_daaf-data" (the
# default install uses "daaf_daaf-data"). Set DAAF_DATA_VOLUME_NAME to a full,
# verbatim volume name to point THIS install at a specific data volume -- the
# escape hatch for sharing ONE research workspace across two installs. When set it
# must match the "name:" under the external "daaf-data" block you uncomment in
# docker-compose.yml. Leave unset for normal installs (the project-prefixed
# default derivation is used, byte-for-byte identical to the historical behavior).
# --- To activate, remove the leading '#': ---
#DAAF_DATA_VOLUME_NAME=daaf_daaf-data
#
# The developer build flag DAAF_DEV also belongs to this install-time family, but
# it is documented alongside the other developer options in section [6].

# [3] Model Routing (advanced)  (restart required)
# ============================================================================
# You only need this section if you point Claude Code at an ALTERNATIVE provider
# -- OpenRouter / GPT / GLM / etc. via Option C in [2], or the provider shim in
# [4]. On a standard Anthropic setup (Options A / B / D / E) the defaults are
# correct and you can skip everything here.
#
# WHY REMAP? DAAF routes specialist subagents to Claude model TIERS: 'opus' for
# high-judgment work (planning, QA review, verification, debugging) and 'sonnet'
# for well-specified work (fetching, profiling, notebook assembly). On a non-
# Claude endpoint those Claude tier aliases don't exist, so you remap them to
# YOUR models. If you set none of these on a non-Claude session, DAAF's model-
# routing guard blocks mismatched Claude-tier dispatches and subagents fall back
# to your session model.
#
# ----------------------------------------------------------------------------
# Two-tier routing: map DAAF's strong / fast tiers to your models
# ----------------------------------------------------------------------------
# Strong tier (Opus-analog) and fast tier (Sonnet-analog).
# Same-window example: openai/gpt-5.6-sol (strong) with
# openai/gpt-5.6-terra (fast); openai/gpt-6-astra also works as the strong tier.
# See the GLM-specific global-window guidance below
# before routing exact GLM and Air together.
# --- To activate, remove the leading '#' and set your model slugs: ---
#ANTHROPIC_DEFAULT_OPUS_MODEL=your-strong-model-slug
#ANTHROPIC_DEFAULT_SONNET_MODEL=your-fast-model-slug
#
# Or switch tiered routing OFF and run every subagent on a SINGLE model:
# --- To activate, remove the leading '#': ---
#CLAUDE_CODE_SUBAGENT_MODEL=your-model-slug
#
# ----------------------------------------------------------------------------
# Session model (the model a session OPENS on)
# ----------------------------------------------------------------------------
# On Option C (OpenRouter) this key works and sets your session model.
# IMPORTANT: on the provider shim (Option F, section [4]) it does NOT take effect
# from this file -- DAAF's settings.json "env" block overrides it; section [4]
# explains how to change the standing default there.
# --- To activate, remove the leading '#': ---
#ANTHROPIC_MODEL=openai/gpt-5.6-sol
#
# ----------------------------------------------------------------------------
# Context window size
# ----------------------------------------------------------------------------
# TL;DR: on a standard Anthropic setup you can ignore this key entirely -- it
# only matters on alternative-provider routes (OpenRouter, GLM, GPT).
#
# Tell Claude Code the real context window so it does not assume ~200K for an
# unknown slug and end sessions early with "Prompt is too long." This override is
# GLOBAL: it applies to the main session and every subagent, not per model. Choose
# one value that is valid for every model the session can route to.
# NOTE: on the ChatGPT-subscription shim lane (Option F alternate lane, section
# [4.3]) the Codex backend enforces a 919k effective input ceiling regardless of
# the model's API-route window -- set 919000 there (see [4.3]), not 1050000.
# --- To activate, remove the leading '#' and set the global value: ---
#CLAUDE_CODE_MAX_CONTEXT_TOKENS=1050000
#
# Exact z-ai/glm-5.2 guidance (current OpenRouter catalogue, 2026-07-15):
# for the recommended 1,048,576 declaration, route the main session and BOTH
# subagent tiers to exact z-ai/glm-5.2 (equivalently, flatten all routing to it):
#ANTHROPIC_MODEL=z-ai/glm-5.2
#ANTHROPIC_DEFAULT_OPUS_MODEL=z-ai/glm-5.2
#ANTHROPIC_DEFAULT_SONNET_MODEL=z-ai/glm-5.2
#CLAUDE_CODE_MAX_CONTEXT_TOKENS=1048576
# This declares PHYSICAL capacity only. GLM still uses DAAF's conservative
# context-quality thresholds (40%/150k, 60%/200k, 75%/250k; whichever fires
# first). If you want z-ai/glm-5.2-air as the fast tier, do not reuse 1048576
# unless you independently verify Air's current physical window and confirm that
# the one global value is valid for every routed model. This runtime path has no
# supported per-model context-window override.
#
# GPT window sizes: the gpt-5.6 family (sol / terra / luna), gpt-6-astra, and
# gpt-5.5 / 5.4 are 1050000 on API/OpenRouter routes; gpt-5.2 is 400000. DAAF keeps Claude
# Code automatic compaction disabled, so CLAUDE_CODE_AUTO_COMPACT_WINDOW is NOT
# an alternative declaration or protection mechanism.
#
# GPT-5.6 FAMILY & TIER-ANALOG NAMING: Sol (strong / Opus-analog), Terra
# (mid / Sonnet-analog), Luna (economy / Haiku-analog) -- all with 1,050,000-token
# windows; the older gpt-5.5 / 5.4 / 5.2 slugs still work. GPT-6 Astra (slug
# gpt-6-astra) is the newer flagship, also with a 1,050,000-token window (128,000
# max output). Context-utilization numbers are ESTIMATES on GPT sessions
# (OpenRouter doesn't serve Claude Code's token-counting endpoint). GPT models use
# DAAF's conservative context-quality thresholds by default; exact gpt-5.6-sol,
# gpt-5.6-sol[1m], gpt-6-astra, and gpt-6-astra[1m] (including provider-prefixed
# forms) share a validated profile that keeps higher validated absolute gates while
# using higher percentages: 60%/300k, 75%/400k, and 90%/500k (whichever fires
# first). Non-Sol/Astra and near-match variants (e.g. gpt-6-astra-pro) remain
# conservative. Physical-window mapping and quality thresholds are separate.
# See the installation guide's "GPT (OpenAI) models via OpenRouter" section for
# current model guidance.
#
# THE [1m] SLUG SUFFIX: appending [1m] to a model slug advertises a 1M window to
# Claude Code, which budgets the full window locally and then strips [1m] before
# sending (so the shim / backend see the bare slug). It is VERIFIED for the
# direct-OpenAI shim lane (Option F in [4]) but UNTESTED on "openai/"-prefixed
# OpenRouter slugs -- so on Option C prefer the explicit
# CLAUDE_CODE_MAX_CONTEXT_TOKENS above. On the ChatGPT-subscription lane ([4.3]),
# the [1m] hint cannot raise the Codex backend's measured 919k ceiling: set the
# override CLAUDE_CODE_MAX_CONTEXT_TOKENS=919000 per section [4.3]. DAAF keeps
# automatic compaction disabled and instead uses the aligned physical-window
# declaration for utilization, statusline rendering, severity, and stop/restart
# guidance.
#
# ----------------------------------------------------------------------------
# Optional Claude Code output budget (restart required)
# ----------------------------------------------------------------------------
# Claude Code defaults CLAUDE_CODE_MAX_OUTPUT_TOKENS to 32000 and supports up to
# 64000. On Claude Code 2.1.202, use the plain decimal value 64000 (not "64K").
# Thinking tokens count toward this output budget. Raising it reserves more of the
# context window for a possible response, leaving less room for conversation
# history and tool results and potentially causing earlier DAAF stop/restart
# guidance; the active provider/model can also impose a lower limit. DAAF
# therefore keeps 32000 as the default and recommends bounded specialist final
# returns even when you opt in.
# Set this in the HOST daaf-docker/environment_settings.txt before starting Claude
# Code/the container; the established host injection flow supplies it at startup.
# --- Optional: remove the leading '#' to opt in to Claude Code's maximum: ---
#CLAUDE_CODE_MAX_OUTPUT_TOKENS=64000
#
#
# ============================================================================
# [4] Alternative Providers & Shim  (rebuild required, once)
# ============================================================================
# Run OpenAI GPT models against your OWN OpenAI API key or your ChatGPT
# subscription, with no gateway in between. OpenAI's API doesn't speak Anthropic's
# wire format, so DAAF ships a small translation shim (scripts/provider_shim/ --
# one auditable file, zero extra dependencies). When DAAF_PROVIDER_SHIM is set,
# the container starts and supervises the shim automatically at boot; there is
# nothing to run manually.
#
# ONE-TIME REBUILD: enabling the shim for the first time requires ONE image
# rebuild (the auto-launch hook is baked into the container entrypoint):
#     bash rebuild_daaf.sh     (macOS / Linux)   |   .\rebuild_daaf.ps1   (Windows)
# After that, config changes here only need the usual container recreate.
#
# Setup guide: user_reference/01_installation_and_quickstart.md, Option F.
#
# ----------------------------------------------------------------------------
# 4.1 Basic shim setup (both auth lanes need these)
# ----------------------------------------------------------------------------
# --- To activate, remove the leading '#' on all five lines: ---
#DAAF_PROVIDER_SHIM=openai
#ANTHROPIC_BASE_URL=http://127.0.0.1:4141
#ANTHROPIC_AUTH_TOKEN=daaf-shim-local
#ANTHROPIC_API_KEY=
#CLAUDE_CODE_DISABLE_FAST_MODE=1
#
# The exact disable value above hides Claude Code's misleading native /fast control
# on GPT routes. Supported Anthropic models retain native /fast. Edit this private
# HOST file yourself: in-container DAAF code cannot access it. Recreate the
# container and start a new Claude session after changing it; no image rebuild is
# required for this setting.
#
# GPT FAST / GPT PRIORITY SPEED BOOST (shim v1.3.9+): OFF by default. One command
# inside the container turns it on, turns it off, or reports where things stand:
#     bash /daaf/scripts/provider_shim/gpt_fast.sh {on|off|status}
# (In a Claude Code session, prefix the same command with `!`.) Changes apply
# immediately -- no restart needed. Turning it `on` requires the
# exact CLAUDE_CODE_DISABLE_FAST_MODE=1 line above, and switching provider
# routes resets the boost OFF until you explicitly turn it back on. One honest
# caveat: requesting the boost doesn't guarantee it was served on any given
# request -- `status` reports the most recent evidence of what actually served.
# Full details: the technical FAQ's GPT Fast entry.
#
# Then pick ONE auth lane below: 4.2 (OpenAI API key, sanctioned) or 4.3 (ChatGPT
# subscription via Codex OAuth, an unofficial dev lane).
#
# MODEL SLUGS: the shim lane is the one place the [1m] window suffix is verified
# (see section [3] for what these keys do). Use BARE OpenAI slugs here -- no
# "openai/" prefix:
# --- To activate, remove the leading '#': ---
#ANTHROPIC_DEFAULT_OPUS_MODEL=gpt-5.6-sol[1m]
#ANTHROPIC_DEFAULT_SONNET_MODEL=gpt-5.6-terra[1m]
#
# GPT-6 Astra is available as an alternative strong-tier slug on this lane --
# gpt-6-astra[1m] (bare; the [1m] hint is verified here). One Astra-specific
# caveat: Astra does NOT support reasoning-effort "none" -- the shim clamps a
# requested "none" to "low" for Astra (see REASONING-EFFORT CONTROL in 4.4).
# --- To activate, remove the leading '#': ---
#ANTHROPIC_DEFAULT_OPUS_MODEL=gpt-6-astra[1m]
#
# CONTEXT WINDOW: CLAUDE_CODE_MAX_CONTEXT_TOKENS is LANE-SPECIFIC -- the two auth
# lanes hit different effective ceilings (the ChatGPT/Codex backend is capped far
# below the model's true 1M window), so it is set per-lane in 4.2 / 4.3 below,
# not here.
#
# SESSION-START MODEL: do NOT set ANTHROPIC_MODEL in this file for the shim -- it
# will not take effect. DAAF's project settings.json sets ANTHROPIC_MODEL in its
# "env" block (shipped default: claude-opus-4-8[1m], since most DAAF users run
# Claude), and a settings.json env value OVERRIDES the container environment
# (verified empirically 2026-07-12). GPT sessions therefore open on the Claude
# default; the first message fails loudly, which makes the needed "/model" switch
# obvious. To make GPT your STANDING default instead, edit the ANTHROPIC_MODEL
# line in /daaf/.claude/settings.json (e.g. to gpt-5.6-sol[1m]) -- see the
# technical FAQ entry "My GPT session starts on a Claude model" for details.
#
# ----------------------------------------------------------------------------
# 4.2 Auth lane A: OpenAI API key  (sanctioned)
# ----------------------------------------------------------------------------
# Get a key: https://platform.openai.com/api-keys
# The legacy shim process still defaults to openai when unset, but a supported GPT
# provider-shim route and its service-tier controller require this exact route value.
# Set it explicitly; unset, case-varied, or whitespace-padded values fail route checks.
# --- To activate, remove the leading '#' on both lines: ---
#SHIM_BACKEND_MODE=openai
#OPENAI_API_KEY=sk-your_openai_key_here
#
# CONTEXT WINDOW (API-key lane): this lane serves the model's full window
# (live-confirmed clean at 400k input, 2026-07-16). Declare the real 1M window
# (1050000 applies to gpt-6-astra on this lane too):
# --- To activate, remove the leading '#': ---
#CLAUDE_CODE_MAX_CONTEXT_TOKENS=1050000
#
# ON on this lane requests GPT Priority (`service_tier:"priority"`). Priority may
# cost extra and depends on provider/model/account eligibility.
#
# ----------------------------------------------------------------------------
# 4.3 Auth lane B: ChatGPT subscription (Codex backend)  (unofficial dev lane)
# ----------------------------------------------------------------------------
# Instead of a pay-per-token OpenAI API key, the SAME shim can route Claude Code
# through your CHATGPT SUBSCRIPTION's Codex backend. Everything else about how
# the shim behaves stays the same on this lane. It reads its sign-in from your
# `codex` login (auth.json).
#
# UNOFFICIAL / DEV-LANE PATH: this reuses Codex's OAuth against an undocumented,
# OpenAI-controlled backend -- NOT an OpenAI-sanctioned API method. It may break if
# OpenAI changes the backend, and you are responsible for compliance with OpenAI's
# terms. The API-key lane (4.2) is the sanctioned fallback.
#
# SETUP CHECKLIST (full walkthrough: user_reference/01_installation_and_quickstart.md,
# "Option F, alternate lane: ChatGPT subscription"; quick version: user_reference/
# 07_faq_technical.md, "Can I use my ChatGPT subscription instead of an OpenAI API key?"):
#   1. CONFIRM CODEX. The pinned Codex CLI ships in every DAAF image; DAAF_DEV=1
#      is NOT required merely to obtain it or log in. Verify inside the container
#      with `codex --version` (expect 0.153.2; 0.153.1 is the minimum that lists
#      gpt-6-astra). If the command is missing, update
#      DAAF and rebuild the image (rebuild_daaf.sh / rebuild_daaf.ps1) so the host
#      build uses the current Dockerfile.
#   2. ENABLE DEVICE-CODE LOGIN FIRST. In your ChatGPT personal-account security
#      settings (chatgpt.com), turn on device-code login. It is OFF BY DEFAULT and
#      is the easy-to-miss step -- `codex login --device-auth` fails without it.
#   3. LOG IN inside the container:  codex login --device-auth
#      (The flag is --device-auth. `codex auth` does NOT exist, and bare
#      `codex login` uses a browser loopback that does not work headless.) It
#      prints a URL + one-time code; open the URL on ANY device (laptop / phone),
#      sign in to ChatGPT, enter the code. No in-container browser, no
#      localhost:1455 loopback, no port forwarding.
#   4. SWITCH THE SHIM ON: set SHIM_BACKEND_MODE=chatgpt below, then recreate the
#      container (docker compose down, then run_daaf.sh / run_daaf.ps1). The shim
#      reads the mode at startup.
#   5. CONFIRM IT WORKS: scripts/provider_shim/logs/shim.log shows
#      backend_mode=chatgpt and healthy 200s; a GPT session runs.
#
# The OAuth access token lasts ~10 days and the shim auto-refreshes it (tokens are
# never logged). If refresh ever fails permanently, the shim log tells you to run
# `codex login --device-auth` again.
#
# Running more than one container? Each container does its OWN `codex login`,
# which creates an INDEPENDENT refresh-token grant -- no credential collision
# between them. They share only your ChatGPT usage pool (the 5-hour + weekly
# caps), so running both draws it down faster. This is the clean way to run
# parallel instances. (By contrast, running several codex-based tools inside ONE
# container off the SAME login can rarely trigger a refresh-token-rotation race;
# give each its own login under a separate CODEX_HOME to isolate them. The two
# OAuth override vars below are the other customization hooks.)
#
# SHIM_BACKEND_MODE switches the shim from the api.openai.com API-key lane to the
# ChatGPT / Codex OAuth lane. With this set, OPENAI_API_KEY / SHIM_BACKEND_API_KEY
# are ignored; the shim reads $CODEX_HOME/auth.json (set by compose to the
# persisted codex-daaf store) for the Bearer and refreshes it automatically.
# --- To activate, remove the leading '#': ---
#SHIM_BACKEND_MODE=chatgpt
#
# CONTEXT WINDOW (chatgpt lane): the Codex subscription backend enforces a much
# lower effective INPUT ceiling than the model's true 1M window -- measured 919000
# on 2026-09-05 for BOTH gpt-6-astra (accept 919,053, reject 922,552) and
# gpt-5.6-sol (accept 910,827, reject 921,973). This supersedes the earlier
# 2026-07-16 Sol-only figure of ~370000. The backend is the ultimate hard ceiling;
# neither [1m] nor any client setting can raise it. Declare 919000 here to align
# Claude Code and DAAF's physical-window accounting with that ceiling. DAAF uses
# the aligned denominator for utilization, statusline rendering, severity, and
# behavioral stop/restart guidance. DAAF keeps automatic compaction disabled and
# does not implement a transport-level request blocker. Big-window GPT slugs on
# this lane are assumed capped the same way until individually measured.
# Re-measure with scripts/provider_shim/probe_context_ceiling.py.
# --- To activate, remove the leading '#': ---
#CLAUDE_CODE_MAX_CONTEXT_TOKENS=919000
#
# ON on this lane requests friendly ChatGPT Fast using canonical Responses wire
# `service_tier:"priority"`. This remains ChatGPT plan/credit usage, NOT OpenAI API
# Priority Processing billing. Availability depends on provider/model/account eligibility.

# CODEX_HOME (chatgpt mode): the directory holding auth.json. Compose already sets
# this to the persisted, backed-up store and pre-creates it on fresh volumes;
# override only to point at a separate per-tool login store for parallel use.
# --- To activate, remove the leading '#': ---
#CODEX_HOME=/home/appuser/.claude/codex-daaf

#SHIM_SANITIZE_TOOLS=0
#
# REASONING-EFFORT CONTROL (shim v1.2.2+): the outbound OpenAI request always
# carries reasoning.effort, resolved by a four-tier precedence chain (first
# present wins): (1) a per-request signal from Claude Code, (2) a "#<effort>"
# suffix you append to a model slug, (3) the SHIM_REASONING_EFFORT env var below,
# (4) the default "high" (parity with DAAF Claude sessions). The "#<effort>"
# suffix works ALONGSIDE the "[1m]" window hint -- Claude Code consumes "[1m]"
# itself and passes "#<effort>" through to the shim, which strips it before the
# request reaches OpenAI. Example per-model override (fast tier at medium effort):
#     ANTHROPIC_DEFAULT_SONNET_MODEL=gpt-5.6-terra[1m]#medium
#
# IMPORTANT (shim v1.2.3+): the /model reasoning-effort selector in the Claude
# Code UI does NOT work for GPT slugs. Claude Code gates effort by model-ID
# pattern and pins "high" on every request for unrecognized (GPT) slugs, so the UI
# selector is inert. As of v1.2.3 the shim treats an inbound "high" as that pin
# (unset) and falls through to your slug / env steer. Steer GPT effort with the
# "#<effort>" suffix (tier 2, above) or SHIM_REASONING_EFFORT (tier 3, below).
#
# SHIM_REASONING_EFFORT (tier 3 of the effort precedence chain): sets
# reasoning.effort when no usable per-request signal and no slug suffix are
# present. Valid values none|low|medium|high|xhigh|max ("max" is supported on the
# gpt-5.6 family and gpt-6-astra). gpt-6-astra does NOT accept "none" -- the shim
# clamps a requested "none" to "low" for Astra.
# Leave unset to use the default "high" (v1.2.2+ always sends an effort now -- the
# old implicit "medium" server default no longer applies). Read at shim startup,
# so a restart is required.
# --- To activate, remove the leading '#': ---
#SHIM_REASONING_EFFORT=
#
# SHIM_TEXT_VERBOSITY (shim v1.2.4+): the outbound OpenAI request always carries
# text.verbosity. Valid values low|medium|high. Default "medium" balances concise,
# decision-focused responses with enough detail for DAAF evidence and caveats;
# "high" adds warmth and volume, while "low" is terse. Set this to dial GPT
# responses that feel too brief or too long. Unset -> "medium". Read at shim
# startup, so a restart is required.
# --- To activate, remove the leading '#': ---
#SHIM_TEXT_VERBOSITY=

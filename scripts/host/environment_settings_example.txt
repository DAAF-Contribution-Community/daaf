# DAAF ENVIRONMENT SETTINGS
# ============================================================================
# HOW TO USE THIS FILE
#   1. Copy this file to environment_settings.txt in your daaf-docker folder:
#          cp environment_settings_example.txt environment_settings.txt          (macOS / Linux)
#          Copy-Item environment_settings_example.txt environment_settings.txt   (Windows PowerShell)
#   2. Turn a setting ON by deleting the single leading '#' on its "#KEY=value"
#      line, then fill in your value. The long "# ..." prose lines are
#      explanations -- leave those commented; only "#KEY=value" lines are meant
#      to be uncommented.
#   3. Apply your change. Most settings need a container recreate; a few need an
#      image rebuild, and a few must be set BEFORE install -- each section's
#      banner carries a lifecycle tag saying which (and the CONTENTS map below
#      summarizes them). The usual recreate: choose "Restart Container" in the
#      DAAF Control Panel, or, by hand:
#          docker compose down
#          bash run_daaf.sh    (macOS / Linux)   |   .\run_daaf.ps1   (Windows)
#   Full walkthrough: user_reference/01_installation_and_quickstart.md
#
# CONVENTIONS USED BELOW
#   #KEY=value   An activatable example. Always flush at column 0 with the '#'
#                immediately in front of the key, never indented, and never with
#                a trailing "# ..." comment on the same line (a value followed by
#                an inline comment breaks some parsers). Delete the one leading
#                '#' to turn it on.
#   # text       An explanatory prose line (it may be indented AFTER the '#').
#   Write values bare: KEY=value with nothing extra -- no quotes around the
#   value and no spaces around the '='. DAAF's readers take the line literally,
#   so quotes or stray spaces can end up inside your value. (Editing on Windows
#   is fine -- Windows line endings are tolerated.)
#   Adjacent #KEY lines introduced with "pick ONE" are mutually exclusive
#   alternatives -- uncomment only the set for the method you chose.
#
# IMPORTANT: environment_settings.txt is gitignored by default. Never commit it
# and never paste real keys or tokens anywhere. This example file holds NO real
# values and sets NOTHING by default -- everything ships commented out, so a fresh
# copy is safe by default.

# ============================================================================
# [1] Install & Update Settings  (set BEFORE install/update)
# ============================================================================
# These DAAF_* settings are read by the host-side launcher and lifecycle scripts
# (install, update, run, backup, rebuild) on your OWN machine -- not only inside
# the container. Because the host scripts read them, they behave a little
# differently from the container-only keys in later sections:
#
#   * For a STANDARD single install, leave everything in this section unset --
#     the defaults reproduce the original behavior exactly.
#   * The multi-instance keys (DAAF_PROJECT_NAME, DAAF_PORT_*) only matter when
#     you run a SECOND DAAF install on the same machine.
#
# WHEN ARE THESE READ? At install time this file may not exist yet -- install is
# what CREATES it. So for a brand-new SECOND instance you set these as real
# environment variables BEFORE the first install/run (export them, or prefix the
# command). AFTER the install exists, this file becomes their permanent home and
# the host scripts read them from here.
#
# LIFECYCLE NUANCE: the section banner's "(set BEFORE install/update)" tag is
# strictly true only for DAAF_PROJECT_NAME, which is fixed at creation time --
# changing it on an existing install detaches it from its data volume. The PORT
# keys CAN be changed later: set the new value here, then recreate the container
# per the header's recreate guidance ("Restart Container" in the DAAF Control
# Panel, or, by hand: docker compose down, then run_daaf.sh / run_daaf.ps1).
# DAAF_BRANCH is likewise read on every update, so it too can change at any
# time.
#
# AUTO-SEEDING: at install time DAAF seeds this file for you from any DAAF_*
# environment variables you had set for the install -- so if you exported
# DAAF_PROJECT_NAME / DAAF_PORT_* / DAAF_BRANCH before installing a second
# instance, they are written here automatically and persist for later updates.
#
# ----------------------------------------------------------------------------
# Update channel: which branch DAAF updates track
# ----------------------------------------------------------------------------
# DAAF_BRANCH selects the git branch that update_daaf.sh (and the control panel's
# update option) pull from. It can live HERE -- persisted for every future update
# -- OR be exported / prefixed for a single update run, in which case the
# environment value wins for that one run:
#
#     DAAF_BRANCH=dev bash update_daaf.sh          (one-off; no export needed)
#
# DEFAULT: main (the stable release branch) when unset.
#
# A release TAG (e.g. v2.1.0) is NOT an update channel. The updater tracks
# BRANCHES only -- it follows a moving branch to pull ongoing changes, whereas a
# tag is a fixed snapshot with nowhere newer to advance to. Concretely:
#
#   * Set DAAF_BRANCH to a tag in your ENVIRONMENT and the updater declines with
#     an explanation and makes NO changes -- it neither silently no-ops nor locks
#     you out. To move an installation onto a specific release, do a FRESH INSTALL
#     pinned to the tag instead (the installer accepts a tag as DAAF_BRANCH).
#   * A tag accidentally written into THIS file is not fatal either: the updater
#     warns and falls back to the default branch for that run (no lockout).
#
# So persist a moving BRANCH name here, never a tag.
#
# --- To activate, remove the leading '#' and set your channel: ---
#DAAF_BRANCH=main
#
# ----------------------------------------------------------------------------
# Multi-instance: run more than one DAAF on the same machine
# ----------------------------------------------------------------------------
# Give each install folder its own project name and host ports so two instances
# never collide. All DAAF scripts read these automatically. Leave everything
# unset for a standard single install -- the defaults match the original behavior
# exactly.
#
# NOTE: if you run `docker compose` commands DIRECTLY (outside the provided
# scripts), also create a .env file in this folder with the same values -- bare
# docker compose does not read environment_settings.txt for these.
#
# Compose project name (prefixes the container and data volume). DEFAULT: daaf
# WARNING: changing this on an EXISTING install detaches it from its current data
# volume -- only set it when creating a NEW second install.
# --- To activate, remove the leading '#': ---
#DAAF_PROJECT_NAME=daaf2
#
# Host ports for the web services. DEFAULTS: 2718 / 2719 / 2720
# (These replace the old "hand-edit docker-compose.yml" method for port changes.)
# --- To activate, remove the leading '#' on the lines you need: ---
#DAAF_PORT_MARIMO=3718
#DAAF_PORT_LOGVIEWER=3719
#DAAF_PORT_VSCODE=3720
#
# Data-volume override (advanced; shared workspace across installs). Normally the
# research workspace lives in a Docker volume named "<project>_daaf-data" (the
# default install uses "daaf_daaf-data"). Set DAAF_DATA_VOLUME_NAME to a full,
# verbatim volume name to point THIS install at a specific data volume -- the
# escape hatch for sharing ONE research workspace across two installs. When set it
# must match the "name:" under the external "daaf-data" block you uncomment in
# docker-compose.yml. Leave unset for normal installs (the project-prefixed
# default derivation is used, byte-for-byte identical to the historical behavior).
# --- To activate, remove the leading '#': ---
#DAAF_DATA_VOLUME_NAME=daaf_daaf-data
#
# The developer build flag DAAF_DEV also belongs to this install-time family, but
# it is documented alongside the other developer options in section [6].

# ============================================================================
# [3] Model Routing (advanced)  (restart required)
# ============================================================================
# You need this section whenever Claude Code talks to anything OTHER than plain
# Anthropic: OpenRouter (Option C in [2] -- whether you use GPT, GLM, or Claude
# models there), a cloud platform (Options D / E, whose placeholder lines sit
# with those options in [2]), or the provider shim in [4]. With an Anthropic API
# key (Option A) or subscription (Option B) the defaults are correct and you can
# skip everything here (except "Session model", if you want a different opening
# model).
#
# WHY REMAP? DAAF routes specialist subagents to Claude model TIERS: 'opus' for
# high-judgment work (planning, QA review, verification, debugging) and 'sonnet'
# for well-specified work (lookups, source research, notebook assembly). Claude
# Code itself also asks for two more tier names: 'haiku' for its own
# housekeeping calls and 'fable' for Anthropic's top tier. On a non-Claude
# endpoint those Claude names don't exist, so you map all four to YOUR models.
# If you set none of these on a non-Claude session, DAAF's model-tier guard
# blocks its Claude-tier specialist dispatches, because they would ask for a
# Claude model your route doesn't serve. Set at least OPUS and SONNET; setting
# all four is recommended.
#
# ----------------------------------------------------------------------------
# Four-tier routing: tell Claude Code which of YOUR models each tier means
# ----------------------------------------------------------------------------
# Set ALL FOUR keys, even though DAAF's own agents only use two of them. In
# plain terms (2026-10-12 user decision for the haiku / fable pair):
#
#   OPUS    The strong tier. DAAF's high-judgment specialists run here -- AND
#           your session should open on it, because DAAF's default session
#           model is the 'opus' tier (see "Session model" below; confirm with
#           /status).
#   SONNET  The fast tier. DAAF's lighter, well-specified specialists run here.
#   HAIKU   Claude Code's own housekeeping calls (naming your session,
#           summarizing it for --resume). DAAF's agents never use it, but
#           Claude Code does. Left unmapped, Claude Code has sent these as
#           Claude Haiku requests that your route rejects (July 2026 shim
#           logs); Claude Code's current docs say they run on your main,
#           pricier model. Map it to your FAST model.
#   FABLE   Anthropic's top tier. DAAF doesn't use it today; map it to your
#           STRONG model so nothing on your route ever asks for a Claude-only
#           model name (for example if someone picks "fable" in /model). One
#           honest note: Claude Code swaps a Fable model for the Opus one in a
#           few places (e.g. Explore, the Auto Mode safety check). Because
#           FABLE and OPUS map to the same model here, the swap lands on the
#           same model. That is our reading of Claude Code's docs, not
#           something we tested. (OpenRouter's own Claude Code guide sets all
#           four, too.)
#
# Recommended same-window GPT set on OpenRouter: openai/gpt-6-sol for FABLE and
# OPUS, openai/gpt-6-luna for SONNET and HAIKU; openai/gpt-6-astra is a premium
# strong option (use it for FABLE and OPUS together), and openai/gpt-6.1-sol is a
# newer strong option on the same terms. Reaching Claude models
# through OpenRouter? Use the matching Claude slugs from OpenRouter's catalogue
# (strong Claude model for FABLE / OPUS, fast one for SONNET / HAIKU). See the
# GLM-specific global-window guidance below before mixing exact GLM and Air.
# --- To activate, remove the leading '#' and set your model slugs: ---
#ANTHROPIC_DEFAULT_FABLE_MODEL=your-strong-model-slug
#ANTHROPIC_DEFAULT_OPUS_MODEL=your-strong-model-slug
#ANTHROPIC_DEFAULT_SONNET_MODEL=your-fast-model-slug
#ANTHROPIC_DEFAULT_HAIKU_MODEL=your-fast-model-slug
#
# Optional, GPT or GLM models on OpenRouter only: if Claude Code shows a notice
# that Auto mode "classifier requests" aren't eligible on your route, this line
# silences it. On DAAF's pinned Claude Code version (2.1.281) the line only hides
# the notice; DAAF has not confirmed the notice or this fix on OpenRouter itself,
# and a future Claude Code may turn Auto mode off on such routes. Leave it unset
# when you reach Claude models (on OpenRouter or Anthropic). Details: technical
# FAQ, "Is Auto mode working on my GPT route?".
# --- Optional: remove the leading '#' to silence the notice: ---
#CLAUDE_CODE_AUTO_MODE_SERVER=0
#
# ONE MODEL FOR EVERYTHING? Set all four keys above to the same slug. (Older
# DAAF docs suggested CLAUDE_CODE_SUBAGENT_MODEL for this. Since Claude Code
# 2.1.251 it only covers subagents that name no model of their own -- and every
# DAAF agent names one -- so it no longer does the job.)
#
# ADVANCED NOTE: Claude Code also has CLAUDE_CODE_SUBAGENT_MODEL_FORCE, which
# makes CLAUDE_CODE_SUBAGENT_MODEL override every subagent's own model. DAAF
# doesn't use it: it reaches only subagents, so your session model, Claude
# Code's housekeeping (HAIKU) calls and the Fable tier would still need mapping
# of their own. Setting all four keys to one model covers all of them.
#
# ----------------------------------------------------------------------------
# Session model (the model a session OPENS on) -- usually nothing to set
# ----------------------------------------------------------------------------
# DAAF's settings.json ships a SOFT default, ANTHROPIC_DEFAULT_MODEL=opus: new
# sessions open on whatever the 'opus' tier means on your route. With the four
# keys above set, that should be your strong model -- no /model switch each
# session. (This follows from how Claude Code resolves the 'opus' name; it
# hasn't been tested on every route. Run /status to see the model you're on.
# Newer Claude Code versions also label the Default row of the /model picker
# "Set by ANTHROPIC_DEFAULT_MODEL" when this default is in effect.)
#
# The soft default steps aside for any choice you make. Claude Code picks the
# opening model in this order -- first match wins:
#   1. the --model flag
#   2. ANTHROPIC_MODEL (the optional key below)
#   3. a "model" value in any settings file -- including the choice /model
#      saves when you press Enter (pressing 's' in the picker instead switches
#      for this session only)
#   4. an organization default model set by a Claude Enterprise admin (direct
#      Anthropic routes only; if the admin makes it override user choices, it
#      also outranks a /model choice and user, project and local settings,
#      though managed settings and --settings still win)
#   5. DAAF's ANTHROPIC_DEFAULT_MODEL=opus
#   6. Claude Code's own default for your account type
#
# OPTIONAL HARD PIN: ANTHROPIC_MODEL re-applies on every launch and overrides
# even a saved /model choice. Most people don't need it. Example use: open every
# session on your FAST model instead of your strong one (bare slug with [1m] on
# the shim lanes, e.g. gpt-6-luna[1m]; provider-prefixed on OpenRouter, e.g.
# openai/gpt-6-luna).
# --- To activate, remove the leading '#' and set your model slug: ---
#ANTHROPIC_MODEL=your-fast-model-slug
#
# NOTE: don't put ANTHROPIC_DEFAULT_MODEL in this file. DAAF's settings.json
# sets that variable, and a settings.json value replaces the same variable from
# this file, so yours would be ignored. Use ANTHROPIC_MODEL or /model instead.
#
# ----------------------------------------------------------------------------
# Context window size
# ----------------------------------------------------------------------------
# TL;DR: on a standard Anthropic setup you can ignore this key entirely -- it
# only matters on alternative-provider routes (OpenRouter, GLM, GPT).
#
# Tell Claude Code the real context window so it does not assume ~200K for an
# unknown slug and end sessions early with "Prompt is too long." This override is
# GLOBAL: it applies to the main session and every subagent, not per model. Choose
# one value that is valid for every model the session can route to.
# NOTE: on the ChatGPT-subscription shim lane (Option F alternate lane, section
# [4.3]) the Codex backend enforces a 919k effective input ceiling regardless of
# the model's API-route window -- set 919000 there (see [4.3]), not 1050000.
# --- To activate, remove the leading '#' and set the global value: ---
#CLAUDE_CODE_MAX_CONTEXT_TOKENS=1050000
#
# Exact z-ai/glm-5.2 guidance (current OpenRouter catalogue, 2026-07-15):
# for the recommended 1,048,576 declaration, map ALL FOUR tiers to exact
# z-ai/glm-5.2, so every model the session can reach -- including the session
# model itself, which follows the OPUS key -- has that window (this is also the
# "one model for everything" setup):
#ANTHROPIC_DEFAULT_FABLE_MODEL=z-ai/glm-5.2
#ANTHROPIC_DEFAULT_OPUS_MODEL=z-ai/glm-5.2
#ANTHROPIC_DEFAULT_SONNET_MODEL=z-ai/glm-5.2
#ANTHROPIC_DEFAULT_HAIKU_MODEL=z-ai/glm-5.2
#CLAUDE_CODE_MAX_CONTEXT_TOKENS=1048576
# This declares PHYSICAL capacity only. GLM still uses DAAF's conservative
# context-quality thresholds (40%/150k, 60%/200k, 75%/250k; whichever fires
# first). If you want z-ai/glm-5.2-air as the fast tier (SONNET / HAIKU), do
# not reuse 1048576 unless you independently verify Air's current physical
# window and confirm that the one global value is valid for every routed model.
# This runtime path has no supported per-model context-window override.
#
# GPT window sizes: the gpt-5.6 family (sol / terra / luna), gpt-6-astra,
# gpt-6-sol, gpt-6-luna, gpt-6.1-sol, and gpt-5.5 / 5.4 are 1050000 on API/OpenRouter routes
# (flagship -pro slugs share their base's window); gpt-5.2 is 400000. DAAF keeps Claude
# Code automatic compaction disabled, so CLAUDE_CODE_AUTO_COMPACT_WINDOW is NOT
# an alternative declaration or protection mechanism.
#
# GPT FAMILY NAMING: the gpt-5.6 family has Sol (strongest), Terra (mid), and
# Luna (fastest / cheapest); GPT-6 has Sol, Luna, and the Astra flagship (128,000
# max output), with no Terra. All have 1,050,000-token windows; the older
# gpt-5.5 / 5.4 / 5.2 slugs still work. DAAF's RECOMMENDED MAPPING (2026-09-29
# user decision, not a validation run): Sol -> strong tier (FABLE + OPUS keys),
# Luna -> fast tier (SONNET + HAIKU keys), shown with gpt-6-sol / gpt-6-luna;
# gpt-6-astra is a premium strong-tier option (5x Sol's price). GPT-6.1 Sol
# (gpt-6.1-sol) is a newer strong-tier option, set on FABLE + OPUS like Sol.
# Context-utilization numbers are ESTIMATES on GPT sessions (OpenRouter
# doesn't serve Claude Code's token-counting endpoint). GPT models use DAAF's
# conservative context-quality thresholds by
# default; exact gpt-5.6-sol and gpt-6-astra (validated), plus gpt-6-sol and the flagship -pro form of all three
# (admitted 2026-09-29 by user policy decision, not validation) and gpt-6.1-sol
# (admitted 2026-10-12 the same way) -- each optionally
# [1m] and provider-prefixed -- share a profile that keeps higher absolute gates
# while using higher percentages: 60%/300k, 75%/400k, and 90%/500k (whichever
# fires first). gpt-6-luna, other GPT variants, and near-match variants remain
# conservative. Physical-window mapping and quality thresholds are separate.
# See the installation guide's "GPT (OpenAI) models via OpenRouter" section for
# current model guidance.
#
# THE [1m] SLUG SUFFIX: appending [1m] to a model slug advertises a 1M window to
# Claude Code, which budgets the full window locally and then strips [1m] before
# sending (so the shim / backend see the bare slug). It is VERIFIED for the
# direct-OpenAI shim lane (Option F in [4]) but UNTESTED on "openai/"-prefixed
# OpenRouter slugs -- so on Option C prefer the explicit
# CLAUDE_CODE_MAX_CONTEXT_TOKENS above. On the ChatGPT-subscription lane ([4.3]),
# the [1m] hint cannot raise the Codex backend's measured 919k ceiling: set the
# override CLAUDE_CODE_MAX_CONTEXT_TOKENS=919000 per section [4.3]. DAAF keeps
# automatic compaction disabled and instead uses the aligned physical-window
# declaration for utilization, statusline rendering, severity, and stop/restart
# guidance.
#
# ----------------------------------------------------------------------------
# Optional Claude Code output budget (restart required)
# ----------------------------------------------------------------------------
# Claude Code defaults CLAUDE_CODE_MAX_OUTPUT_TOKENS to 32000 and supports up to
# 64000. On the pinned Claude Code 2.1.281, use plain decimal 64000 (not "64K").
# Thinking tokens count toward this output budget. Raising it reserves more of the
# context window for a possible response, leaving less room for conversation
# history and tool results and potentially causing earlier DAAF stop/restart
# guidance; the active provider/model can also impose a lower limit. DAAF
# therefore keeps 32000 as the default and recommends bounded specialist final
# returns even when you opt in.
# Set this in the HOST daaf-docker/environment_settings.txt before starting Claude
# Code/the container; the established host injection flow supplies it at startup.
# --- Optional: remove the leading '#' to opt in to Claude Code's maximum: ---
#CLAUDE_CODE_MAX_OUTPUT_TOKENS=64000
#
#
# ============================================================================
# [4] Alternative Providers & Shim  (rebuild required, once)
# ============================================================================
# Run OpenAI GPT models against your OWN OpenAI API key or your ChatGPT
# subscription, with no gateway in between. OpenAI's API doesn't speak Anthropic's
# wire format, so DAAF ships a small translation shim (scripts/provider_shim/ --
# one auditable file, zero extra dependencies). When DAAF_PROVIDER_SHIM is set,
# the container starts and supervises the shim automatically at boot; there is
# nothing to run manually.
#
# ONE-TIME REBUILD: enabling the shim for the first time requires ONE image
# rebuild (the auto-launch hook is baked into the container entrypoint):
#     bash rebuild_daaf.sh     (macOS / Linux)   |   .\rebuild_daaf.ps1   (Windows)
# After that, config changes here only need the usual container recreate.
#
# Setup guide: user_reference/01_installation_and_quickstart.md, Option F.
#
# ----------------------------------------------------------------------------
# 4.1 Basic shim setup (both auth lanes need these)
# ----------------------------------------------------------------------------
# --- To activate, remove the leading '#' on all six lines: ---
#DAAF_PROVIDER_SHIM=openai
#ANTHROPIC_BASE_URL=http://127.0.0.1:4141
#ANTHROPIC_AUTH_TOKEN=daaf-shim-local
#ANTHROPIC_API_KEY=
#CLAUDE_CODE_DISABLE_FAST_MODE=1
#CLAUDE_CODE_AUTO_MODE_SERVER=0
#
# The exact disable value above hides Claude Code's misleading native /fast control
# on GPT routes. Supported Anthropic models retain native /fast. Edit this private
# HOST file yourself: in-container DAAF code cannot access it. Recreate the
# container and start a new Claude session after changing it; no image rebuild is
# required for this setting.
#
# AUTO MODE (recommended on both shim lanes): CLAUDE_CODE_AUTO_MODE_SERVER=0
# silences Claude Code's "classifier requests ... isn't eligible because your
# requests go through 127.0.0.1:4141" notice. On DAAF's pinned Claude Code version
# (2.1.281) nothing changes otherwise: Auto mode keeps working, and its safety
# checks still run through the shim on your GPT model, exactly as before. Claude
# Code calls this a temporary setting, and a third-party report says later Claude
# Code releases may only offer Auto mode where the provider supports it (the shim
# never can), so a future update may turn Auto mode off on GPT routes. DAAF
# re-checks this before moving its pinned version (technical FAQ: "Is Auto mode
# working on my GPT route?"). Do NOT set it on Anthropic routes.
#
# GPT FAST / GPT PRIORITY SPEED BOOST (shim v1.3.9+): OFF by default. One command
# inside the container turns it on, turns it off, or reports where things stand:
#     bash /daaf/scripts/provider_shim/gpt_fast.sh {on|off|status}
# (In a Claude Code session, prefix the same command with `!`.) Changes apply
# immediately -- no restart needed. Turning it `on` requires the
# exact CLAUDE_CODE_DISABLE_FAST_MODE=1 line above, and switching provider
# routes resets the boost OFF until you explicitly turn it back on. One honest
# caveat: requesting the boost doesn't guarantee it was served on any given
# request -- `status` reports the most recent evidence of what actually served.
# Full details: the technical FAQ's GPT Fast entry.
#
# Then pick ONE auth lane below: 4.2 (OpenAI API key, sanctioned) or 4.3 (ChatGPT
# subscription via Codex OAuth, an unofficial dev lane). Using a university or
# company AI gateway instead? Skip 4.1 to 4.3 and use the complete preset in 4.5.
#
# MODEL SLUGS: the shim lane is the one place the [1m] window suffix is verified
# (see section [3] for what these four keys do -- set all four). Use BARE OpenAI
# slugs here -- no "openai/" prefix -- and keep [1m] on every one of them.
# gpt-6-sol / gpt-6-luna are the recommended pair but are UNTESTED on both shim
# lanes: the shim forwards any slug unchanged, while DAAF's recorded shim-lane
# tests used gpt-5.6-sol and gpt-6-astra. If OpenAI rejects a GPT-6 slug, use
# gpt-5.6-sol[1m] / gpt-5.6-luna[1m] instead. Why the HAIKU line matters here:
# left unmapped, Claude Code has sent its housekeeping calls as Claude Haiku
# requests that OpenAI doesn't serve (the July 2026 ChatGPT-lane shim logs show
# dozens of such rejected requests); Claude Code's current docs say they run on
# your main, pricier model.
# --- To activate, remove the leading '#' on all four lines: ---
#ANTHROPIC_DEFAULT_FABLE_MODEL=gpt-6-sol[1m]
#ANTHROPIC_DEFAULT_OPUS_MODEL=gpt-6-sol[1m]
#ANTHROPIC_DEFAULT_SONNET_MODEL=gpt-6-luna[1m]
#ANTHROPIC_DEFAULT_HAIKU_MODEL=gpt-6-luna[1m]
#
# GPT-6 Astra is available as an alternative strong-tier slug on this lane --
# gpt-6-astra[1m] (bare; the [1m] hint is verified here). Use it on BOTH strong
# lines (FABLE and OPUS) in place of gpt-6-sol[1m]; the fast lines stay as they
# are. One Astra-specific caveat: Astra does NOT support reasoning-effort "none"
# -- the shim clamps a requested "none" to "low" for Astra (see
# REASONING-EFFORT CONTROL in 4.4).
# --- To activate, remove the leading '#' (replaces the two Sol lines): ---
#ANTHROPIC_DEFAULT_FABLE_MODEL=gpt-6-astra[1m]
#ANTHROPIC_DEFAULT_OPUS_MODEL=gpt-6-astra[1m]
#
# GPT-6.1 Sol (gpt-6.1-sol[1m]) is another strong-tier option on the same terms:
# put it on BOTH strong lines in place of gpt-6-sol[1m]. Like gpt-6-sol it is
# UNTESTED on the shim lanes, and its ChatGPT-lane ceiling is not yet measured
# (DAAF assumes the same 919000 cap as the other flagships until it is).
#
# CONTEXT WINDOW: CLAUDE_CODE_MAX_CONTEXT_TOKENS is LANE-SPECIFIC -- the two auth
# lanes hit different effective ceilings (the ChatGPT/Codex backend is capped far
# below the model's true 1M window), so it is set per-lane in 4.2 / 4.3 below,
# not here.
#
# SESSION-START MODEL: nothing extra to set. DAAF's default session model is
# the 'opus' tier, so with the four lines above in place your sessions should
# open on your strong GPT model by themselves -- no per-session /model switch
# and no settings.json edit. (This follows from how Claude Code resolves the
# 'opus' name; confirm it with /status the first time.) To open on a different
# model, pick it in /model and press Enter -- Claude Code remembers that choice
# for new sessions -- or set the optional ANTHROPIC_MODEL hard pin from
# section [3] (bare slug with [1m] here, e.g. gpt-6-luna[1m]). If sessions open
# on a model you didn't expect, see the technical FAQ entry "My session opens
# on a different model than I expected".
#

#CLAUDE_CODE_MAX_CONTEXT_TOKENS=1050000

# 4.3 Auth lane B: ChatGPT subscription (Codex backend)  (unofficial dev lane)
# ----------------------------------------------------------------------------
# Instead of a pay-per-token OpenAI API key, the SAME shim can route Claude Code
# through your CHATGPT SUBSCRIPTION's Codex backend. Everything else about how
# the shim behaves stays the same on this lane. It reads its sign-in from your
# `codex` login (auth.json).
#
# UNOFFICIAL / DEV-LANE PATH: this reuses Codex's OAuth against an undocumented,
# OpenAI-controlled backend -- NOT an OpenAI-sanctioned API method. It may break if
# OpenAI changes the backend, and you are responsible for compliance with OpenAI's
# terms. The API-key lane (4.2) is the sanctioned fallback.
#
# SETUP CHECKLIST (full walkthrough: user_reference/01_installation_and_quickstart.md,
# "Option F, alternate lane: ChatGPT subscription"; quick version: user_reference/
# 07_faq_technical.md, "Can I use my ChatGPT subscription instead of an OpenAI API key?"):
#   1. CONFIRM CODEX. The pinned Codex CLI ships in every DAAF image; DAAF_DEV=1
#      is NOT required merely to obtain it or log in. Verify inside the container
#      with `codex --version` (expect 0.153.2; 0.153.1 is the minimum that lists
#      gpt-6-astra). If the command is missing, update
#      DAAF and rebuild the image (rebuild_daaf.sh / rebuild_daaf.ps1) so the host
#      build uses the current Dockerfile.
#   2. ENABLE DEVICE-CODE LOGIN FIRST. In your ChatGPT personal-account security
#      settings (chatgpt.com), turn on device-code login. It is OFF BY DEFAULT and
#      is the easy-to-miss step -- `codex login --device-auth` fails without it.
#   3. LOG IN inside the container:  codex login --device-auth
#      (The flag is --device-auth. `codex auth` does NOT exist, and bare
#      `codex login` uses a browser loopback that does not work headless.) It
#      prints a URL + one-time code; open the URL on ANY device (laptop / phone),
#      sign in to ChatGPT, enter the code. No in-container browser, no
#      localhost:1455 loopback, no port forwarding.
#   4. SWITCH THE SHIM ON: set SHIM_BACKEND_MODE=chatgpt below, then recreate the
#      container: choose "Restart Container" in the DAAF Control Panel (or, by
#      hand: docker compose down, then run_daaf.sh / run_daaf.ps1). The shim
#      reads the mode at startup. If this is the first time you turn the shim
#      on, choose "Rebuild Container" instead (see the [4] banner above).
#   5. CONFIRM IT WORKS: scripts/provider_shim/logs/shim.log shows
#      backend_mode=chatgpt and healthy 200s; a GPT session runs.
#
# The OAuth access token lasts ~10 days and the shim auto-refreshes it (tokens are
# never logged). If refresh ever fails permanently, the shim log tells you to run
# `codex login --device-auth` again.
#
# Running more than one container? Each container does its OWN `codex login`,
# which creates an INDEPENDENT refresh-token grant -- no credential collision
# between them. They share only your ChatGPT usage pool (the 5-hour + weekly
# caps), so running both draws it down faster. This is the clean way to run
# parallel instances. (By contrast, running several codex-based tools inside ONE
# container off the SAME login can rarely trigger a refresh-token-rotation race;
# give each its own login under a separate CODEX_HOME to isolate them. The two
# OAuth override vars below are the other customization hooks.)
#
# SHIM_BACKEND_MODE switches the shim from the api.openai.com API-key lane to the
# ChatGPT / Codex OAuth lane. With this set, OPENAI_API_KEY / SHIM_BACKEND_API_KEY
# are ignored; the shim reads $CODEX_HOME/auth.json (set by compose to the
# persisted codex-daaf store) for the Bearer and refreshes it automatically.
# --- To activate, remove the leading '#': ---
#SHIM_BACKEND_MODE=chatgpt
#
# CONTEXT WINDOW (chatgpt lane): the Codex subscription backend enforces a much
# lower effective INPUT ceiling than the model's true 1M window -- measured 919000
# on 2026-09-05 for BOTH gpt-6-astra (accept 919,053, reject 922,552) and
# gpt-5.6-sol (accept 910,827, reject 921,973). This supersedes the earlier
# 2026-07-16 Sol-only figure of ~370000. The backend is the ultimate hard ceiling;
# neither [1m] nor any client setting can raise it. Declare 919000 here to align
# Claude Code and DAAF's physical-window accounting with that ceiling. DAAF uses
# the aligned denominator for utilization, statusline rendering, severity, and
# behavioral stop/restart guidance. DAAF keeps automatic compaction disabled and
# does not implement a transport-level request blocker. Big-window GPT slugs on
# this lane are assumed capped the same way until individually measured.
# Re-measure with scripts/provider_shim/probe_context_ceiling.py.
# --- To activate, remove the leading '#': ---
#CLAUDE_CODE_MAX_CONTEXT_TOKENS=919000
#
# ON on this lane requests friendly ChatGPT Fast using canonical Responses wire
# `service_tier:"priority"`. This remains ChatGPT plan/credit usage, NOT OpenAI API
# Priority Processing billing. Availability depends on provider/model/account eligibility.
#
# CODEX_HOME (chatgpt mode): the directory holding auth.json. Compose already sets
# this to the persisted, backed-up store and pre-creates it on fresh volumes;
# override only to point at a separate per-tool login store for parallel use.
# --- To activate, remove the leading '#': ---
#CODEX_HOME=/home/appuser/.claude/codex-daaf
#
# CODEX DELEGATION (shim v1.3.0+, chatgpt lane): the shim delegates token refresh
# to the codex CLI (the single writer of auth.json). The two knobs below tune that
# delegated call; the defaults are correct for the standard image.
# SHIM_CODEX_BIN: path to the codex binary the shim invokes for the delegated auth
#   refresh (default "codex" -- resolved on PATH).
# SHIM_CODEX_TIMEOUT_S: seconds to wait for that invocation (default 30).
# --- To activate, remove the leading '#' on the lines you need: ---
#SHIM_CODEX_BIN=
#SHIM_CODEX_TIMEOUT_S=
#
# Troubleshooting (inside the container):
#     codex --version                                          (confirm the standard-image Codex CLI is present)
#     bash /daaf/scripts/provider_shim/start_shim.sh --status  (is the shim up?)
#     cat /daaf/scripts/provider_shim/logs/shim.log            (look for backend_mode=chatgpt + 200s)
#   login fails immediately   -> device-code login not enabled in ChatGPT settings (step 2)
#   codex: command not found  -> update DAAF + rebuild so the current Dockerfile is used
#   shim log says to re-login -> token refresh failed; run `codex login --device-auth` again
#

# 4.4 Advanced shim tuning (defaults are correct for OpenAI; rarely needed)
# ----------------------------------------------------------------------------
# Network / backend overrides (SHIM_BACKEND_API_KEY defaults to OPENAI_API_KEY):
# --- To activate, remove the leading '#' on the lines you need: ---
# DEFAULT: 4141 is the default port; the line below shows it, so uncommenting it changes nothing.
#SHIM_PORT=4141
# SHIM_BACKEND_BASE_URL is WHERE the shim sends your requests. Left unset, the
# API-key lane uses OpenAI itself (https://api.openai.com/v1, shown below). Set it
# to any OpenAI-compatible service that offers OpenAI's Responses API, such as a
# university or company AI gateway (4.5 below has a complete preset). Paste the
# base URL, usually ending in /v1; a trailing "/" or "/responses" is removed for
# you (shim v1.4.7+).
#SHIM_BACKEND_BASE_URL=https://api.openai.com/v1
#SHIM_BACKEND_API_KEY=
#
# SHIM_STRIP_MODEL_PREFIX: a literal prefix stripped from model ids before the
# backend; only needed with prefixed slugs -- leave unset for the bare slugs shown
# in 4.1.
# --- To activate, remove the leading '#': ---
#SHIM_STRIP_MODEL_PREFIX=openai/
#
# SHIM_SANITIZE_TOOLS: sanitization is ON by default (it strips known GPT tool-
# call quirks: empty pages:"", Agent isolation fills, redundant sandbox flags --
# each otherwise costs a wasted error round-trip). Set to 0 ONLY when benchmarking
# shim-routed models (DAAFBench must see raw model behavior). The flag is read at
# shim startup, so a restart is required.
# --- To activate, remove the leading '#': ---
#SHIM_SANITIZE_TOOLS=0
#
# REASONING-EFFORT CONTROL (shim v1.2.2+): the outbound OpenAI request always
# carries reasoning.effort, resolved by a four-tier precedence chain (first
# present wins): (1) a per-request signal from Claude Code, (2) a "#<effort>"
# suffix you append to a model slug, (3) the SHIM_REASONING_EFFORT env var below,
# (4) the default "high" (parity with DAAF Claude sessions). The "#<effort>"
# suffix works ALONGSIDE the "[1m]" window hint -- Claude Code consumes "[1m]"
# itself and passes "#<effort>" through to the shim, which strips it before the
# request reaches OpenAI. Example per-model override (fast tier at medium effort):
#     ANTHROPIC_DEFAULT_SONNET_MODEL=gpt-6-luna[1m]#medium
#
# IMPORTANT (shim v1.2.3+): the /model reasoning-effort selector in the Claude
# Code UI does NOT work for GPT slugs. Claude Code gates effort by model-ID
# pattern and pins "high" on every request for unrecognized (GPT) slugs, so the UI
# selector is inert. As of v1.2.3 the shim treats an inbound "high" as that pin
# (unset) and falls through to your slug / env steer. Steer GPT effort with the
# "#<effort>" suffix (tier 2, above) or SHIM_REASONING_EFFORT (tier 3, below).
#
# SHIM_REASONING_EFFORT (tier 3 of the effort precedence chain): sets
# reasoning.effort when no usable per-request signal and no slug suffix are
# present. Valid values none|low|medium|high|xhigh|max ("max" is supported on the
# gpt-5.6 family and gpt-6-astra). gpt-6-astra does NOT accept "none" -- the shim
# clamps a requested "none" to "low" for Astra. DAAF has not checked which levels
# gpt-6-sol, gpt-6-luna, and gpt-6.1-sol accept.
# Leave unset to use the default "high" (v1.2.2+ always sends an effort now -- the
# old implicit "medium" server default no longer applies). Read at shim startup,
# so a restart is required.
# --- To activate, remove the leading '#': ---
#SHIM_REASONING_EFFORT=
#
# SHIM_TEXT_VERBOSITY (shim v1.2.4+): the outbound OpenAI request always carries
# text.verbosity. Valid values low|medium|high. Default "medium" balances concise,
# decision-focused responses with enough detail for DAAF evidence and caveats;
# "high" adds warmth and volume, while "low" is terse. Set this to dial GPT
# responses that feel too brief or too long. Unset -> "medium". Read at shim
# startup, so a restart is required.
# --- To activate, remove the leading '#': ---
#SHIM_TEXT_VERBOSITY=
#

# ----------------------------------------------------------------------------
# 4.6 Codex CLI settings (config.toml) from this file
# ----------------------------------------------------------------------------
# The Codex CLI keeps its settings in config.toml inside the container. You never
# edit that file yourself: add numbered DAAF_CODEX_CONFIG_<N> lines here instead,
# and DAAF writes them into config.toml every time the container starts. Each line
# is one Codex setting, written as  setting.name=value  (the same form as
# `codex -c setting.name=value`). Lines apply in number order; a later line wins.
# Setting names come from the Codex configuration reference:
# https://developers.openai.com/codex/config-reference
#
# HOW TO WRITE THE VALUE: wrap the whole value in single quotes, as in the
# examples. Docker Compose keeps everything inside single quotes exactly as typed
# (no $ substitution), so the double quotes Codex needs around text survive. A
# plain word without quotes also works (it is read as text). Do not add a comment
# after the value on the same line.
#
# Never paste a key or password into these lines; DAAF refuses values that look
# like credentials -- use env_key/env_http_headers to point at an environment
# variable instead. (A header your gateway needs goes under env_http_headers as
# header name = the NAME of an environment variable holding its value.)
#
# What happens to the file: DAAF marks config.toml as its own on the first line,
# and from then on DAAF owns it. Remove a DAAF_CODEX_CONFIG line and recreate the
# container, and the setting is gone. Anything Codex itself writes into that file
# (for example when you tell it to trust a folder) is replaced at the next
# container start, so set lasting options with DAAF_CODEX_CONFIG lines, as in the
# second example below. If config.toml was written by someone else, DAAF leaves it
# alone and puts its version next to it as config.toml.daaf-generated. These
# settings affect the Codex CLI only; the GPT shim takes its settings from the
# SHIM_* lines above.
#
# Did it work? Inside the container run
#     bash /daaf/scripts/provider_shim/start_shim.sh --status
# The line starting "CODEX CONFIG:" says what DAAF wrote at the last start and
# how many lines had problems; the reasons (never your values) are in
# scripts/provider_shim/logs/codex_config.log.
# --- To activate, remove the leading '#' on the lines you need: ---
#DAAF_CODEX_CONFIG_1='model_reasoning_effort="high"'
#DAAF_CODEX_CONFIG_2='projects={"/daaf"={trust_level="trusted"}}'
#
#

# Developer tooling (framework developers only)  (rebuild required)
# ----------------------------------------------------------------------------
# DAAF_DEV is an OPT-IN, BUILD-TIME flag. Set it to 1 to have the Docker image
# additionally install the in-container test toolchain (shellcheck, bats,
# PowerShell 7, Pester, PSScriptAnalyzer) and the `gh` CLI used with GH_TOKEN
# below -- so you can run DAAF's own shell and PowerShell test suites inside the
# container and reproduce what CI runs. Codex is standard-image software and does
# not require DAAF_DEV=1:
#     bats tests/bash/
#     pwsh -NoProfile -Command "Invoke-Pester -Path ./tests/powershell/"
#
# This is a BUILD flag, not a runtime setting: it only takes effect at
# `docker compose build`, so after changing it you must rebuild (rebuild_daaf.sh /
# rebuild_daaf.ps1). When unset or 0 (the default for every normal install), NONE
# of this tooling is installed and the image is identical to a standard build --
# leaving it off costs you nothing. (DAAF_DEV is part of the install-time family
# in section [1]; it is documented here with the other developer options.)
# --- To activate, remove the leading '#': ---
#DAAF_DEV=1

# ----------------------------------------------------------------------------
# GitHub CLI token (GH_TOKEN)  (framework developers only, restart required)
# ----------------------------------------------------------------------------
# GH_TOKEN authenticates the GitHub CLI (`gh`), which is installed ONLY when you
# build with DAAF_DEV=1 (above). Framework developers use `gh` to inspect CI runs
# and logs, open / work PRs and issues, and as git's HTTPS credential helper for
# pushing over HTTPS. Leave this unset if you are not doing framework development
# -- a normal install has no `gh` binary and no use for it.
#
# Unlike DAAF_DIAG_BUILD (a one-off shell prefix, NOT a key for this file),
# GH_TOKEN IS a persistent environment_settings.txt key: it is injected into the
# container environment at startup via docker-compose env_file, and `gh` reads it
# directly with no `gh auth login` (it takes precedence over any stored credential
# and survives image rebuilds).
#
# Recommended token: a classic Personal Access Token with `repo` + `workflow`
# scopes (repo access, HTTPS push, PR / issue access, CI logs). Create one at:
# https://github.com/settings/tokens
# IMPORTANT: never commit your real token -- not here, not anywhere.
# --- To activate, remove the leading '#': ---
#GH_TOKEN=ghp_your_token_here
#
# ----------------------------------------------------------------------------
# Build diagnostics (DAAF_DIAG_BUILD) -- NOT a key for this file
# ----------------------------------------------------------------------------
# DAAF_DIAG_BUILD is NOT a persistent environment_settings.txt key -- do not set it
# here. It is a one-off, run-time shell PREFIX for a SINGLE install / rebuild
# invocation. Set it only when a build failed with truncated output (a line like
# "[output clipped, log limit 2MiB reached]"); it routes the build through a
# custom buildx builder with raised step-log limits so you can see the full,
# unclipped error. Note: that builder uses a SEPARATE build cache (the first such
# build is slower) and loads the finished image back into Docker when done.
# Usage (prefix the command; do NOT persist it):
#     bash:       DAAF_DIAG_BUILD=1 bash rebuild_daaf.sh
#     PowerShell: $env:DAAF_DIAG_BUILD = "1"; .\rebuild_daaf.ps1
